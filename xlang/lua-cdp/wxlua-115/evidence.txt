SUMMARY: heap-use-after-free ../src/wxcore_menutool.cpp:1387 in wxLua_wxMenu_delete_function

Two distinct allocations: the Lua userdata handle for `submenu` (gc-tracked by
wxLua) and a separate 256-byte C++ wxMenu (new'd at menutool.cpp:1243).
AppendSubMenu transfers ownership of the C++ submenu to the parent (stored in a
wxMenuItem, deleted by ~wxMenu), but wxLua does NOT un-track the submenu userdata
— so its __gc deletes the already-freed C++ object a second time. NOT a borrowed
pointer into one managed object.

===== CONTROL: FIXED (ded8e0a) — no UAF =====
NO-CRASH: reached end
No AddressSanitizer report. The fix adds `%ungc` to AppendSubMenu, emitting
`if (wxluaO_isgcobject(L, submenu)) wxluaO_undeletegcobject(L, submenu);`
(wxcore_menutool.cpp:197) so the submenu is removed from wxLua's gc-object list
the moment ownership crosses to the parent; GC #2 is then a no-op.

The differential (double-delete UAF on the parent commit, clean run on the fix)
is what makes this a verified reproduction rather than an incidental crash.
