Evidence for lua-openssl #141 — CAPTURED BY US (not an upstream quote).

Env: OpenSSL 1.1.1w (built from source, shared + enable-crypto-mdebug +
     -fsanitize=address), PUC Lua 5.4.7 (shared toolchain, built shared),
     gcc 15.2 AddressSanitizer.
Binding: lua-openssl @ 0017afa (parent of the fix a436c36 = vulnerable tree).
Trigger: xlang/lua-cdp/lua-openssl-141/trigger.lua (verbatim issue #141 repro).

Two distinct allocations: the Lua full userdata (the cipher handle, a boxed
pointer created by PUSH_OBJECT) and a separate 168-byte EVP_CIPHER_CTX
allocated by libcrypto (CRYPTO_zalloc via EVP_CIPHER_CTX_new). close() and __gc
are the SAME C function openssl_cipher_ctx_free (cipher_ctx_funs registers both
{"close",...} and {"__gc",...} to it); close() frees the ctx without nulling the
boxed pointer, so __gc frees it again. NOT a borrowed pointer into a Lua string.

Why libcrypto is ASan-built: with an uninstrumented libcrypto the second free
crashes as a bare SEGV inside EVP_CIPHER_CTX_reset (it derefs the freed ctx,
whose header ASan has overwritten, before reaching the free() ASan intercepts).
Instrumenting libcrypto turns that into the labelled heap-use-after-free below.

The vulnerable openssl_cipher_ctx_free (src/cipher.c:546-554):
    EVP_CIPHER_CTX *ctx = CHECK_OBJECT(1, EVP_CIPHER_CTX, "openssl.evp_cipher_ctx");
    lua_pushnil(L);
    lua_rawsetp(L, LUA_REGISTRYINDEX, ctx);
    EVP_CIPHER_CTX_cleanup(ctx);   // line 551 — reads freed ctx on the 2nd call
    EVP_CIPHER_CTX_free(ctx);      // line 552 — the free (1st call)
    return 0;
CHECK_OBJECT reads *(EVP_CIPHER_CTX**) from the userdata box; close() never
nulls it, so __gc dereferences the stale pointer.

===== CONTROL: FIXED (a436c36) — no UAF =====
NO-DOUBLE-FREE
No AddressSanitizer report. The fix ("fix issue #141") adds, in
openssl_cipher_ctx_free:  `if(!ctx) return 0;` and, after the frees,
`FREE_OBJECT(1)` == `*(void**)lua_touserdata(L,1) = NULL`, nulling the boxed
pointer so the __gc call re-reads NULL and returns without touching freed memory.

The differential (heap-use-after-free on the parent, clean on the fix) is what
makes this a verified reproduction rather than an incidental crash.
