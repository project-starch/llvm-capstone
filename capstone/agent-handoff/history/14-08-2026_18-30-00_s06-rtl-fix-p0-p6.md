# S-06 RTL fix — untagged 128-bit ldc/stc high-half loss — resolved in RTL (P0–P6)

**Date:** 2026-08-14
**Branch:** `fpga-testing-dev-s06fix` (off `fpga-testing-dev`)
**Status:** core fix complete and sim-validated; board synthesis pending (external);
one documented residual (AMO tag resurrection).

## What S-06 was

An untagged 128-bit `ldc`/`stc` round trip lost or corrupted the high 64 bits on silicon
(and would forge tags). Root cause was 13 sites (D1–D13) across the memory subsystem and
pipeline; the decisive ones: the two dcache read gates zeroing the raw high dword (D1/D2),
single-bank/single-beat untagged writes (D3/D4), the `decompress_cap→compress_cap` round
trip minting `0x0800_0000|(C[20:14]<<20)` for 16 KiB-aligned cursors (D5/D6), and — a live
forgery hazard — `st_wr_cap = |wr_user_i` / `is_cap_req = |dcache_data.user` letting nonzero
plain metadata SET a tag (D7). It had forced three software workarounds, all NOT VIABLE on
silicon (ISSUES.md:766).

## The fix (Option A, the user's contract: untagged ldc/stc copies all 128 bits verbatim,
tag clear; tagged handling untouched)

A real 1-bit tag rides beside every 64-bit compressed-metadata lane (64→65) from the shadow
regfile through the pipeline, the dcache req/resp, the wbuffer, the CSRs and the dom-switch
context. Two choke points make it sound with zero Anvil fat_cap_t changes:
- ingestion forces NOT_CAP when tag=0 (`decompress_cap_tagged`, stashing the raw 64 bits in
  the dead `bound_start`), so raw data aliasing a cap type can never act as a capability;
- egress is bijective (`compress_cap` NOT_CAP branch returns the stash verbatim; tag :=
  cap_type != NOT_CAP), so compress∘decompress is the identity for untagged values.
Memory width is opcode-driven and tag writes are tag-value-driven, never `|metadata|`-driven
— this STRENGTHENS the no-forge invariant.

bit-identical: verdict + cycles + trace-hash + exception-count across all tests)

- **P1** (683d3db4c) memory width/tag decouple — bit-identical to P0.
- **P2** (f8791f4ac) pipeline 65-bit tag lanes — bit-identical to P1.
- **P3** (c5bb34575) the semantic flip — `s06-lowhalf-zero{,-swap}` FAIL→SUCCESS; two
  interim-tag regressions found and fixed (cap CSR readback, dom-switch restore).
- **P4** (d0b12e6d4) read-path ungate + real granule tag consumed end to end;
  `untagged-ldc-stc-128` flipped to assert the fix and passes. A THIRD sync site surfaced
  as a deadlock: `commit_stage`'s LDC clear-commit pulse decided from metadata CONTENT while
  the load unit decided from the tag — an LDC of raw data aliasing a linear type committed a
  store the load unit never enqueued, wedging the drain. Fixed by gating the commit pulse on
  the real tag (mirrors `ldc_clear_needed`). Lesson: the linear-clear condition lives in
  THREE places (load_unit, DYN `check_load_data`, commit_stage) — the Anvil header even says
  "keep in sync"; P4 initially updated only two.
- **P5a** (c68d48c09) stored tags for cap CSRs; CPMP grants require the tag (closes
  csrrw-raw→CPMP forging physical-memory protection). Bit-identical to P4.
- **P5b** (db48cc190) dom-switcher carries a real 129-bit tag lane (Anvil rebuilt); all
  interim content-rules retired except the deliberate pc_cap one (branch_unit gates raw
  operands, so pc metadata is genuine-or-zero by construction). Bit-identical to P5a.
- **P6** tag-based tracer classification; security directed tests; AMO residual documented.

## Known residual — AMO tag resurrection (NOT closed, separate follow-up)

An AMO on a capability granule leaves both the L1 `cap_tag_q` and the DRAM tag byte set, so a
later reload resurrects a "capability" over AMO-written scalar data (invariant I4 — a real
forgery path, and in scope of the user's "ordinary data cannot set valid tags" even though
the plan scoped the rider as optional/separate). The one-line rider (ATOMIC_REQ into the
tag-write FSM) was attempted and REVERTED: an AMO's ATOP completion does not emit the store
B-response that decrements `tag_wr_pend`, so the next load's tag-read wedges in TAG_WAIT
(reproduced in sim — the post-AMO reload never retires). A correct rider must also invalidate
the line's L1 `cap_tag_q`; both are cache-coherence changes out of the S-06 core scope. Repro:
`verif/tests/custom/capstone/s06sec-amo-no-resurrect.S` (kept out of the testlist so it does
not fail the gate; currently TESTNUM=3 = resurrected).
