## Step 1b: the format in the core — site census and a proposed staging (design, nothing built)

**Census** (read-only, on capstone-ariane b1-r75d 1c5d31474; lines spot-checked against source: ariane_pkg.sv:211-218,
:660, :917-919, :988; ex_stage.sv:89; load_store_unit.sv:1374; capstone_flu_unit.anvil:505; capstone_dyn_unit.anvil:623):
- **Widths.** CAP_SLOT_W 25 and CAP_GEN_W 30 give CAP_ID_W 55 (ariane_pkg.sv:211-213). But CAP_MD_W is derived as
  `CAP_SLOT_W + 1 + 64` (:214), and so is CAP_PCMD_W (:215), because today the lane's top field IS the slot. Under
  Sublet that field is bounds[25:0], so the derivation changes and does not simply follow CAP_SLOT_W (it would give 96, not
  91). About 45 parameterised sites still assume "lane top = slot": cap_lane / cap_slot / decompress_cap, csr_regfile's
  ~28 slot registers, branch_unit, frontend, issue_read_operands, pmp_data_if and load_unit.
- **Literal slot/id slices outside the record:** about 25 in ex_stage, 16 in load_store_unit, 3 in commit_stage, 4 in
  pmp_data_if and 2 in cva6. Most are `[24:0]` slot compares; ex_stage carries eleven `logic[54:0]`-style channel
  widths.
- **Compressed-word positions** (the type at [29:27], bounds E at [26]/[16:14]/[2:0]): about 12 sites in ex_stage,
  commit_stage, issue_read_operands and load_unit. These are the decode shim's sites.
- **Pack/unpack:** ids55_pack_lo / ids55_unpack_word / ids55_cursor (ariane_pkg.sv:914-923) with 3 callers, plus THREE
  inline copies of the unpack in ex_stage (:978-980, :1018-1020, :1634-1635).
- **Anvil:** about 27 id-typed fields in capstone_unit.anvilh (`logic[55]` channel payloads, `logic[25]` probe), the
  89-bit raw lane in capstone_defs.anvilh and capstone_dom_switcher.anvilh, and id literals in flu (5), dyn (6) and
  dom_switcher (16). rev_node splits the id at `[0+:25]` / `[25+:30]` at about 40 sites and pads the slot into its
  30-bit links at 46 sites.
- **The record (step 2):** about 47 layout sites in ex_stage plus most of capstone_rev_node.anvil.
- **Bounds:** cursor_outside_window's E < 50 limit (ariane_pkg.sv:988) is taken from the 64-bit cursor, and is to be
  re-derived. The genesis end MEM_END is 2^40 (capstone_flu_unit.anvil:505); the ariane_pkg.sv:841 comment's "2^63" is
  stale. The CAPBOUND length cap is flu:475.

**The entanglement that decides the staging.** The id's WIDTH cannot change without the record:
- the record's links and the invalidation/fill buses are 30 bits (ex_stage.sv:89 and four more ports), which a 31-bit
  slot does not fit;
- rev_node splits ids at fixed positions in about 40 places.
So widening the id in step 1b pulls step 2 into it.

**Proposed staging (for review before any RTL):**
- **1b, format at the boundary.** The memory doublewords, the register lane, the 38-bit cursor and the decode shim take the
  Sublet LAYOUT: hi = generation << 32 | slot << 1 | bounds[26], lo = bounds[25:0] << 38 | address[37:0], lane
  {bounds[25:0], tag, hi}. The id VALUES keep today's internal widths (generation 30, slot 25), zero-extended into the
  Sublet fields at pack and checked zero at unpack.
  - Touched: the pack/unpack and its three inline copies, cap_lane / decompress_cap, the CAP_MD_W derivation, the
    compressed-word positions (the shim), the cursor rule and the window limit.
  - Untouched: rev_node and the record.
  - Its directed check: a capability round-trips through STC/LDC and a context save, with the reference model's
    encoder as the oracle (the codec's 1,006,498 vectors).
- **2, id and record together.** CAP_GEN_W 32, CAP_SLOT_W 31; the 128-bit record; liveness as a generation match; the
  walker at 5:9:9:8 over slot[30:0]; the Anvil id types.
- **3, the instructions,** as in the scope document.
- **Open in 1b:** a stored capability whose high generation or slot bits are set cannot come from this hardware's
  allocator. Whether unpack faults on one, or clears its tag, is for the semantics owner (the runtime lane).

**Sharpened before any RTL** (an advisor review, and the reference model read at capstone-qemu c1985bb529):
- **What 1b's gate no longer tests.** The scope document named the format's new synthesis risk as "the 8 extra bits on
  every id compare". With today's id widths kept, 1b's synthesis-only gate reads the shim's constant-folding and the
  one-bit lane change, not that risk. The risk moves to step 2, which then carries the id widening, the record and the
  walker together. Step 2 should split: the 5:9:9:8 walker only becomes live for slots of 2^26 and above, so it can trail
  the id/record widening as its own gate.
- **The reference's Sublet mode** (`x-capstone-ids=63`):
  - It KEEPS the supervisor: capstone_supervisor.c reads Sublet tables, so CSRUNV stays.
  - It makes 14 instructions illegal (cause 2) before any other check: TIGHTEN, DELIN, SEAL, MREV, INIT, SPLIT, DROP,
    REVOKE, CALL, RETURN, CAPENTER, the CJALR domain switch, CSSUPERVISE and CSRETIRE (trans_capstone.c.inc:25-41).
    1b's decoder follows it: those become illegal rather than no-ops, so the twin and the RTL agree.
  - Four of them (DELIN and TIGHTEN on the share path, MREV and REVOKE in create_domain) are on today's monitor's
    EXECUTED boot path.
  - **So 1b has no silicon key until the runtime lane's monitor redesign lands.** Its evidence is the synthesis gate
    and directed simulation only.
- **The plain-load rule keeps its shape.** A plain load of a tagged granule's FIRST doubleword reads the address, now
  zero-extended from 38 bits (cap.h:262-266, `cap_ids_packed_addr`, through helper_capstone_wide_load). The second
  doubleword reads raw: generation << 32 | slot << 1 | bounds[26] (op_helper.c:1106-1113).
  - Raw readers of a stored capability's word therefore change what they see: lo[63:38] is now bounds, not a slot.
  - The B residue census's sites are the may-differ class for the sweep.
  - Before the sweep, every test that reads a stored capability word raw (sweep-compare-rvfi.py finds them) is written
    as may-differ; everything through LDC/STC must be identical.
- **The 38-bit cursor is a reach question.** Under the reference's Sv39 policy a Sublet cursor must be below 2^38
  (cap.h cap_addr_ok, cap_compress.c:208-210), so a capability whose cursor lies in Sv39's upper half has no encoding.
  Asked of the runtime lane: does anything on the native route with CSRUNV kept hold one (frame contents, CSMINT grants,
  CSCHECK's page capabilities)? The genesis end MEM_END = 2^40 (flu:505) goes on the same list.
- **Mutants, one per unpack copy.** The unpack lives in four places: ariane_pkg and three inline copies in ex_stage
  (the LDC result, the STC result bypass and the RAWLANE bypass); the context save is a fifth path. Each gets a
  forced mutant left on the ids55 rule, and a directed arm must catch each. A split brain between the copies is silent
  otherwise.
  - Memory-image positive control: format-checks.c's literal (page 0x80009000, generation 1, slot 5:
    lo 0x0004000080009000, hi 0x10000000b).

**The runtime lane's rulings on 1b's open questions (2026-11-22):**
- **Genesis end: 2^38.** It is the format's own address limit (cap_compress.c:210 refuses a cursor >= 2^38 for any type),
  so it does not depend on the platform, and every board address lies below it.
  - KNOWN DIVERGENCE: the reference gives genesis a1 an end of 1 << 63 (op_helper.c:4466, "TODO: should be 2**64").
    The runtime lane asks for the reference to move to 2^38. The RTL is not built to 2^63.
- **A stored word with the high generation or slot bits set: clear the tag at unpack (fail closed).** No new fault path
  enters the LSU verdict cone. On 1b's hardware the case is unreachable: the allocator stays at 30/25 bits, 1b has no raw
  tag moves, and an ordinary store clears the tag.
  - A 1b-only rule: step 2 removes it when the widths widen.
  - The reference keeps the tag and would refuse at the liveness check. That divergence is unobservable in a
    differential, because the twin produces no such id on 1b-shaped runs.
- **The 38-bit cursor on the native route: OPEN.** The runtime lane's read-only census is running. Nothing that assumes
  "no upper-half cursor" is built until it reports.

## Step 1b, first cut: capstone-ariane b5b1-format 647e4e43d (on b1-r75d 1c5d31474)

**Design choice: the memory boundary only.** Registers keep today's internal lane {slot 25, tag, metadata 64}, and only
the two stored doublewords take the Sublet layout. In the reference's ids=63 mode every live capability is NONLIN with
every right: genesis is NONLIN (op_helper.c:4495), and the type and rights writers are illegal. So nothing is lost
across a store, and most of the census's ~45 "lane top = slot" sites need no change in 1b. What changes:
- ariane_pkg's fmt_* functions (pack lo/hi, unpack lane/cursor/word, zext38, fail-closed on high id bits);
- their callers: STC, the context save, the switcher row, the plain-load rule, and ex_stage's three inline copies;
- the 2^38 cursor rule in R-60's closed form and in its oracle;
- the 13 illegal opcodes;
- the S-06 sim invariant.
All of it sits behind CAPSTONE_SUBLET_FMT, and `+define+CAPSTONE_IDS55_FMT` restores the ids55 build on the same tree.

**Owed in 1b:** the genesis capability NONLIN, with its end at 2^38. Anvil has no preprocessor, so the define cannot
reach capstone_flu_unit.anvil; the options are a build-selected source file, or an SV override at the FLU result.

**Pre-registered arm:** verif/tests/custom/capstone/sublet-fmt.S, expectations in sublet-fmt.expect, both written and
pushed before any simulation of them. Eleven readings per build. A model-free cross check: the 27-bit bounds read from
the Sublet words ({hi[0], lo[63:38]}) must equal the ids55 metadata word's [26:0] (0x103000 here).

**Q1 answered by the runtime lane (2026-11-22): NO software on the native route creates or holds a capability with a
cursor >= 2^38.**
- The CSMINT grants are user VAs, validated (capstone_vm.c:2229-2231). The binfmt grants sit below mmap_base. The
  CSCHECK/CSMINT page capabilities are PAs below 0xc000_0000.
- CSCRATCH and CEPC hold kernel VAs as untagged integers.
Follow-ups:
- **The monitor's genesis END moves to 2^38:** region_nend[2] (sbi_capstone_dom.c:35), cap_above (dom.c:124-125), and
  cpmp(2) from the boot SPLITs (sbi_capstone_init.S:47-48). This goes on the monitor-redesign list.
- **The 2^38 edge:** under Sv39, TASK_SIZE is exactly 2^38, so a grant with cursor = end (the stack grant) could carry
  0x40_0000_0000. The runtime lane adds a cursor < 2^38 / end <= 2^38 check to the module under the Sublet build.

**KNOWN BREAK in 647e4e43d, found by reading source (the runtime lane's item 3): the switcher's hidden snapshot of the S
caller.**
- Row 0 of the caller snapshot is {slot, pc_next_tag, pc_next_metadata, pc_next} (capstone_dom_switcher.anvil:21), and
  pc_next_tag is (pc_metadata type != NOT_CAP) (commit_stage.sv:691, :925).
- The frontend's PC metadata changes only on capability control flow (frontend.sv:454-490), never at a trap or mret. So
  an S kernel entered from the capmode monitor carries the monitor's code-capability metadata, and its row 0 is saved
  TAGGED with a kernel-VA pc.
- ids55 restores that through sext39. Sublet's zext38 does not, and the caller would resume at a corrupted pc. The
  va-runv family cannot show it: its S callers run at physical 0x8000_xxxx.
- Untagging that row looks unsafe, because the stale metadata appears to be how M's code capability survives an S
  excursion.
- Options (A) keep the ids55 packing for the hidden snapshot only, (B) store row 0 raw and re-adopt its metadata on
  restore, (C) re-establish M's PCC at trap entry. They are with the runtime lane, which first answers whether software
  reads the snapshot's capability words.

**The runtime lane's ruling on the snapshot (2026-11-22): option (A).** The hidden caller snapshot (frame +1024 and up,
the caller's ids 0..67) keeps a lossless internal format. Only the software-visible frame slots (+0..+944) take
Sublet.
- No software parses the snapshot's capability words in the board configuration (c5a_model=1). The only writes into
  +1024..+1976 are on non-c5a paths (capstone_vm.c:1217, checked-copy-dom.h:238). Under c5a, export/import is the RTL's
  detach/adopt, which keeps the bytes without interpreting them.
- The reference keeps the caller lossless too: save_state / restore_state (capstone_supervisor.c:156, :202) hold it as
  host-side fat state, never compressed to either format. So (A) is the RTL matching the reference.
- **Constraint, binding:** the snapshot is switcher-private. Its format is NOT Sublet and appears in no software-visible or
  ABI-documented layout. If B5b-2's trap route exposes it, it gets its own decision then.
- **Design:** the switcher marks each data request with a snap bit (offset from dom_base >= 1024). store_unit and
  load_unit pack and unpack snapshot rows with the ids55 packing, whose sext39 rebuilds an Sv39 kernel pc, and frame
  slots with Sublet. The bit travels in dom_switch_data_req (Anvil and SV) and through the load unit's buffer entry.
- **Owed directed check:** a CSRUNV round trip whose S caller has an upper-half pc and register cursor.

## Genesis, and the monitor under Sublet (2026-11-22)

- **No RTL genesis change is owed.** In this RTL the only genesis is CAPENTER (capstone_flu_unit.anvil: the PCC and the
  two genesis capabilities, MEM_END 2^40 as rd's end), and 1b makes CAPENTER illegal, as the reference's ids=63 mode
  does. So under Sublet the genesis path, MEM_END included, is unreachable.
  - The reference agrees structurally (capstone-qemu c1985bb529 cpu.c:1734-1741): ids=63 needs the virtual profile
    because the physical one depends on linear capabilities, sealing and CAPENTER. Its only genesis is the CAPENTER
    helper.
- **The runtime lane's ruling: the redesigned monitor runs in integer M and holds no capability of its own.** No M-only
  debug mints (CAPCREATE/CAPTYPE/CAPBOUND/CAPPERM) go into it: they are RTL-only and absent from the reference, so they
  would split the twin from the silicon on the monitor's own path. The debug mints stay a test-harness tool.
  - So the monitor-END list of Q1 (region_nend[2], cap_above, cpmp(2)) is MOOT under Sublet: with no CAPENTER there are
    no genesis or cpmp capabilities to bound. The redesign must not carry them as dead code.
  - **CSMINT in hardware is required** (step 3). The reference has it legal in S and M under ids=63, memory-to-memory,
    with scalar slot and descriptor addresses (trans_capstone.c.inc:568). With it, the kernel mints and the monitor's
    CSMINT emulation goes away.
  - **CSCHECK has no Sublet form in the reference** (insn32.decode has csmint and csrunv, no CSCHECK). On P1 it is the
    monitor's emulation, built on page capabilities derived from its CAPENTER genesis, so under Sublet it cannot exist
    as written. The native route's checked copy needs a decision, which is not 1b's and is taken when step 3 is
    designed. The options are hardware CSCHECK (added to the reference first) or the B5b-2 path. It is the runtime
    lane's.
- **So 1b (and 1c) have no silicon key.** Their evidence is synthesis plus directed simulation, and nothing on the board
  runs the native route on a Sublet bitstream before step 3 and the checked-copy decision. A full build of 1b alone is
  not requested; it is batched with a later step.

**va-runv's instrument fix, with its must-fail control** (capstone-ariane e06e918aa, ids55 build since va-runv needs
CAPENTER): the caller's s2 is now read through `mv t2, s2`. It reads 0x1234, and under the simulation-only mutant

## Step 2, the record and the unit: a design proposal (2026-11-22, nothing built)

**The reference record** (capstone-qemu c1985bb529, cap_rev_table_abi.h, the SUBLET section) is a different design, not
a widened copy of today's:
- 128 bits: generation 127:96, previous 95:65, next 64:34, depth 33:3, zero 2:0.
  word 0 = {next[29:0], depth[30:0], 000}; word 1 = {generation[31:0], previous[30:0], next[30]}.
- No parent and no VALID, LINEAR or FREE flag. A record is live for exactly the id {its generation, its slot}.
- Generations advance at RELEASE, never at allocation, and a slot retires at generation 2^32 - 1. The free list runs
  through next.
- An allocation takes the free head, else the next never-used slot, and decides resources in four steps (29, a slot,
  30, or an untagged 0 under NOGROW).
- The paged root: the header at +0..+56 (capacity|flags, next, free head|count, allocations, magic, retired, growth),
  then 32 root entries at +64. A slot splits 5:9:9:8.

Today's unit (capstone_rev_node.anvil, ~1,000 lines) implements a 137-bit record with parent links, three flags and the
operations TIGHTEN/DELIN/MREV/INIT/SPLIT/DROP/REVOKE/kill/deepen/retire. 1b already makes all of those illegal. Under
ids=63 only these reach the unit:
- the liveness QUERY: every LSU, CPMP and PC probe;
- CDERIVE (allocate a child);
- CREVOKE (single operand: release the operand's subtree, the run after it with depth greater than its own);
- CSMINT (R at depth 0);
- CRENEW.

**Proposal:** step 2 is a NEW, smaller lifetime unit for the Sublet format, selected by CAPSTONE_SUBLET_FMT, with the
same ports as today's (the spatial-only core swapped in a stub the same way). Today's unit stays untouched for the
ids55 build. Widening the existing unit in place would edit its ~40 fixed id splits and 46 link pads for semantics it

**The ops, in the reference's order** (helper_csderive / helper_cskill / helper_csrenew, cap_rev_tree.c):
- **open**, every lifetime op, with nothing cached across ops:
  - read header quadwords 0 and 1, and 2 and 3 when paged;
  - check what cap_rev_table_open checks: capacity, flags, next, magic, growth, reserved, the free count and retired
    bounds, and the first two free entries (shape, links, distinct, below next);
  - check that the fresh candidates are reachable.
  - Any failure answers 29. Header words read in an op stay in flops for that op only.
- **resolve**: slot >= 2 and below next and capacity; record reachable; generation not retired and equal to the id's.
  Otherwise dead (25).
- **CDERIVE_S** (dyn_unit, in order):
  1. 24 (parent untagged or size tagged);
  2. mrev check: 29 invalid, 25 dead;
  3. size zero, window or compact round trip: 29;
  4. derive commit: open, resolve again, then the four-step allocation decision (29 / proceed / 30 / FAIL). The
     allocation is the free head, else next (writing word 1 = 0). Then the reference's derive: read node.next and check
     it links back; a node at depth_max answers 30; put child, next and node; note_alloc.
  - The child's rights are the parent's & RWX (the shim then gives it 1b's every-right view).
  - FAIL writes an untagged 0 to rd.
- **CREVOKE_S**: 24, then kill: open (29), resolve (25), then `retire`:
  - check pass over the run, bounded by next visits;
  - commit pass: each run record released (generation + 1, or retired), pushed through next;
  - splice prev and stop, then release the operand.
  - The free head and count, and retired, sit in flops across the op, and header quadwords 1 (and 2) are written once
    at its end. The reference writes them per release, and the final memory is identical.
- **CRENEW**: 24, then init: open (29), resolve (25), then:
  - in place while the next generation is issuable (2a's bound);
  - else the four-step decision, which takes the slot before the run is pushed;
  - FAIL writes an untagged 0 to rd, also when rd = rs1.
- **Two passes, not one.** Every check precedes the first write (the reference, and the abi header's own rule). So a
  run's records are read twice and written once. The ABI comment's "the processor reads and writes each record once
  (Section 5)" cannot hold together with that rule for an unbounded run. The paper's text does not carry the sentence
  (searched in paper-nested-allocators, every origin branch, read-only); only the abi comment does. See question Q4.

**The query without `next`** (Q2):
- The reference's resolve also requires slot < next. The query and the taps cannot afford a header read per probe, and
  a cached next is stale after the kernel's growth.
- Proposal: an ABI rule that the kernel publishes every record page with word 1 = the retired word (0xffffffff << 32)
  and word 0 = 0, including the first page's reserved slots 0 and 1.
  - A never-used slot then reads retired, so dead, in hardware and in the twin alike.
  - The reference's fresh allocation already overwrites word 1 with 0 (sublet_alloc).
- Without the rule, a capability naming a never-used slot whose page holds a matching generation reads live in hardware
  and dead in QEMU. Only a capability from another table can name such a slot.

**What the hardware does not check** (Q3, a recorded divergence):
- the whole free list at the first open after the srevroot edge (QEMU's cap_rev_table_free_list_ok). Hardware finds a
  bad entry when it comes within two of the head;
- range_ok on table addresses;
- the query on a table that fails validation (hardware reads the record only, where QEMU fails every reference check).

**The revocation-cache taps decide liveness from the unit's intent, not from the record.** A Sublet record has no
VALID bit, and a released record holds its NEXT generation. A tap decoding it as live would install {g + 1, s} as a live
write. That keeps the ALLOW record for {g, s}, because rvc_ok_kill needs a write with nodeval 0 to the index
(load_store_unit.sv:1633-1635, b5b1-format 8cbf393d4): a stale ALLOW, which is a use-after-revoke. So the unit's write payload carries two flags
of its own beside the record words:
- **live:** the fill tap's nodeval. It is 1 on derive and put writes and 0 on a release or a retire.
- **invalidate:** ex_stage's revnode_invalidation_valid_o.
CRENEW in place is the one write that needs both. It must kill every cached verdict for the slot and install the new
id live. How the LSU cache resolves an invalidation and a fill of the same index in one cycle is read before it is
built. If it resolves dead, the new id reads a false 25, which is a functional error, not a fail-closed one. The walker's
injected DEAD response (pw_dead_rv_q) must read as retired under Sublet, so that the read tap fills it dead.

**Memory port:** the existing walker and record TLB (ex_stage, 5:9:9:8 from root+64), reached through flops on both
sides (the cone-cut finding). The new unit adds no combinational path from its own state into a D$ request. The walker
widens to 31 bits only with 2b.
