## Why (the cost table, sim, fdk and the batch)

Extra cycles per op against the plain twin in the same page state: ldc +0.99 on a hit, +0.5 on a miss; stc +2.92
(fdk) / +1.69 (batch) on a hit; movc +1.61. The large term is per PAGE: on a page that has held a capability a load
miss costs +16.0 and a store miss +44.4 sim cycles whatever the opcode (cost-tab.S, capstone-ariane
perf/cost-tab-fdk / perf/cost-tab-batch). The TWC covered 32 KB of data, the same reach as the L1D; a tag write
invalidated its entry; and with a write-through L1D every store that drains on a marked page writes a tag byte unless
the TWC holds it with the same value. Sim cycles here come from `axi2mem`, which serves one AXI transaction at a time;
what transfers to silicon is the COUNT of tag reads and writes, hence the events.

## Audit (claim-auditor, on 54bdfd53c, by reading)

- REFUTED, fixed in bbfc6abc1: an install to the same index in the cycle before a store's merge latch leaves the
  registered lookup showing the store's word while the entry took another's; the merge then wrote one word's bytes
  under the other's atag and kept it valid. The merge now writes the atag too.
- REFUTED, NOT a lever in this bitstream: removing the TWC clear on a page fill. Tag words are not page-aligned
  (`CAP_TAG_MEM_BASE = 0xBC2D2D2D`), so a page's first and last tag words are shared with its neighbours and can be
  cached with the page's leftover bytes. Safe narrowing for later: invalidate only those two indices.
- SUPPORTED: config B is the base's behaviour apart from the events; no forward reference, no second driver, no loop.
- No page goes from marked to unmarked except at reset, which also resets the TWC.
- Found on the way, filed separately: ISSUES R-73 (the debug module's system-bus master writes DRAM around the adapter).

## The fill-time window: the testbench cannot create it (amendment before F's full build, 2026-11-14)

An rtl-oracle read found the ordering is NOT structural in the RTL: the miss unit masks only reads behind a valid
MSHR, and writes still go unless they hit the same 16-byte line (`wt_dcache_missunit.sv:455`, `:169-170`, `:236`); the write
buffer's drain is not gated on reads (`wt_dcache_wbuffer.sv:291`); the adapter pops the load at its TAG_RD grant
(`wt_axi_adapter.sv:564`), and the FILL branch has no in-flight term (`:807-815`). So on silicon a fill can start
with a tag read in flight. The F full build was held pending tw-fill-gap at memory delays 40 and 80 (criteria: one
`fill-enter inflight=1`, else void; 12 traps / 0x18; no S-06).

**Delay 40 read VOID for F and F2** (24 fill entries each, all `inflight=0`; board lane's read). The cause is the
instrument: the testbench memory `axi2mem` is one state machine (`corev_apu/axi_mem_if/src/axi2mem.sv:56`, `IDLE /
READ / WRITE / SEND_B`) that raises `aw_ready` / `ar_ready` only in IDLE (`:105-145`) and stays in READ to the last
beat (`:175-210`). A write is never accepted while a read is open, and a fill enters only on its write's grant
(`axi_wr_gnt`, `:807-815`), so in this testbench a fill can never start mid tag-read at ANY memory delay. The criterion
is unattainable here; the delay-80 runs will read void for the same reason.

**Decision (RTL lane): F's full build is RELEASED on a948e4134.** Its fill-window handling is, by reading,
equivalent to the base TWC in service on boards 1-3 (fdk, the batch): in both, no install becomes valid during a fill
(base: valid bits cleared every TAG_FILL cycle; F: the epoch bumps at entry and no epoch is written during the fill or
in the entry cycle), and a beat landing after the fill's writes is poisoned (`fill_req & axi_wr_gnt`, unchanged). So
holding F does not reduce exposure: the same unmeasured window is in every bitstream in service. NOT measured, stated
as such. F2's handling differs (no bump), stays out, and is the one most in need of the measurement.

**Next instrument:** a sim-only hold on the tag read's R beat inside the adapter (`axi2mem` completes the read at once
and accepts the store's write; the adapter presents the beat to its install logic N cycles later, keeping
`tag_rd_inflight_q` set), which models silicon's concurrent write acceptance. Run on base, F and F2 with tw-fill-gap;
if the BASE forges, that is a finding on the bitstreams in service and goes to ISSUES and the lead at once.
