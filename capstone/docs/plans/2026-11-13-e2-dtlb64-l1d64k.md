# E2: a larger DTLB and a larger L1D, as one-change bitstreams (plan and pre-registration, 2026-11-13)

*RTL lane. The lead's decision (relayed by the SPEC lane): cache sizing is Capstone's engineering choice, because
16-byte capabilities double pointer footprint. Condition: each change must be PROVEN on silicon to help and not hurt.
So each is a separate bitstream, differing from the sealed base in exactly one config value, and the SPEC lane A/Bs
it on the same board against that base (problem rows mcf, gcc train01, perl, plus one control row; N=2 where the
effect is under ~3 %). Combinations come only after each single change has shown positive.*

## Base and variants

- **Base:** `caplifive_ids55-native-tagcache-mlp-fpieee-hpmreplay_5f41c486e` (sha256 b457b57a...; dev 2a79fb76b09a).
- **Variants** (capstone-ariane, all pushed; each one commit on 5f41c486e, all in
  `core/include/capstone_cv64a6_imafdc_sv39_config_pkg.sv`):

| variant | branch, commit | change | name if built |
|---|---|---|---|
| DTLB 64 | perf/ids55-e2-dtlb64 097401036 | DataTlbEntries 16 -> 64 (fully associative) | `...-hpmreplay-dtlb64_<sha>` |
| L1D 64 KiB | perf/ids55-e2-l1d64k a7f95f371 | DcacheSetAssoc 8 -> 16, DcacheByteSize 32 -> 64 KiB (16-byte lines; 4 KiB per way, the VIPT limit) | `...-hpmreplay-l1d64k_<sha>` |
| both (held) | perf/ids55-e2-both 96bd38219 | both of the above | only after each single change is positive |

**Known side effect in the L1D variant, left alone so that it stays one change.** The HPM eviction event (18)
compares `miss_vld_bits` with `8'hFF` (`perf_counters.sv:132`), so with 16 ways it misreads. It affects counter 18
only, not cycles.

## Gates passed before synthesis

- **Lint** (rtl-lint-gate.sh), each variant: PASS, identical to the base on every counter (LATCH 44, MULTIDRIVEN 3,
  UNOPTFLAT 39, UNDRIVEN 25, UNUSEDSIGNAL 1480, SELRANGE 100, the rest 0 or at baseline).
- **Simulation smoke test** against the base on the same tree footing (sim11-wt .sup/e2base, e2tlb, e2l1d, e2both;
  the tag tests, the cost arms with HPM, vb-trans-vp2, va-runv, va-flat):
  - DTLB 64: identical in values, retired counts and cycles.
  - L1D 64 KiB: identical in every value; only cycle fields move.
    - tag-mlp's M6: 0x29d1 -> 0x2869.
    - A miss arm: +84 cycles.
    - tag-word-cache: it hits the 4 M cycle limit on the base and COMPLETES in 981,033 cycles with 64 KiB.

## Prediction (the cache model on the native route, mcf test; perf/dcm-native/)

The model is the DCM L1D/DTLB model: 256 sets x 16-byte lines, 8/16/32 random ways; DTLB 16/32/64 entries, true
LRU. The model code is byte-identical in both arms.
- Capstone feed: a hook in a private copy of the qemu55 native twin.
- riscv-base feed: a TCG plugin on kit-profq's QEMU.

Both arms ran to completion with specdiff 2/2. Misses:

| | L1D 32 KiB (today) | 64 KiB | DTLB 16 (today) | DTLB 64 |
|---|---|---|---|---|
| Capstone | 3.35 G | 3.16 G (-5.6 %) | 906 M | 524 M (-42 %) |
| riscv-base | 2.47 G | 2.30 G | 770 M | 434 M |

- **Calibration.** The model reads about 0.43-0.45 G under the silicon L1D-miss counts on both arms (2.90 G / 3.80 G
  in the backlog), a constant offset consistent with counting loads only and user-mode only. Its differences are the
  usable part. The module-route model of 8 Nov agrees within ~1 %.
- **Predicted cycles on mcf (Capstone),** misses saved x a per-miss penalty that is not yet measured:
  - DTLB 64: about 5.7-11.5 G cycles, roughly 4-8 %.
  - L1D 64 KiB: about 3.8 G cycles, roughly 2.5 %.
- The board A/B's HPM counters (L1D and DTLB misses with cycles, on the base run) pin the penalty.
- gcc train01 and perl are being modelled; their readings are added here before the A/B.

## Pre-registration of the builds (written before either gate result)

**Synthesis-only gate**, against the base's synthesis checkpoint on leffe:
1. Mapping peak in the base's class (5,447 MB).
2. Loops: check_timing 0, "Found timing loop" 0, Synth 8-326 0, LUTLP-1 0.
3. Area, report only, floor first: module, core and TOP each 0 +/- 2,500 LUT. The change's own instance rows are read
   (the DTLB under the MMU; wt_dcache LUT/FF/BRAM). The worst setup-path family is named against the base: both
   changes sit on the load path.

**Full build**, launched on a gate pass without a further go (the SPEC lane's decision):
- placed LUT reported against the base's 181,565. A change bigger than the floor is expected for DTLB 64, so this is
  a report, not a key.
- congestion: placer max <= 5, post-route router effective <= 5;
- 0 routing errors;
- 0 loops;
- WNS inside the null band of the base's -15.077, reported as a value.
- **If routing fails, or WNS falls outside the band, it is a NEGATIVE result** (the lead's condition: nothing is tuned
  to fit). Readings: placed area, congestion and the census; no WNS.
- sha256 recorded.

**Silicon (the SPEC lane's):** each variant against the base, back to back on the same board, the same kit and
images; mcf, gcc train01, perl, plus a control row; N=2 where the predicted effect is under ~3 % (the L1D variant).

## Pre-registration: L1D 48 KiB / 12 ways + victim fold (conditional; written before any build)

**Condition.** It launches only if the 64 KiB build fails to route or reads WNS outside the band, and only if its own
lint and smoke test against the base are clean. That is the SPEC lane's word, given in advance. It runs on whichever
host frees first.

**The change.** capstone-ariane perf/ids55-e2-l1d48k **b9ab75c41** (pushed), on 5f41c486e. It is TWO changes, read on
silicon as "48 KiB + fold":
1. config: DcacheSetAssoc 12, DcacheByteSize 49152 (256 sets x 16 B);
2. wt_dcache_missunit.sv: the victim LFSR is $clog2(ways) = 4 bits wide and can name ways 12..15, which do not exist;
   those values fold onto 8..11. A power-of-two way count never takes the fold.

Name: `caplifive_ids55-native-tagcache-mlp-fpieee-hpmreplay-l1d48k_b9ab75c41`.

**Predicted.**
- Area: the 64 KiB gate read wt_dcache +7.8 k LUT and BRAM 24 -> 48, so 12 ways is roughly +3.9 k LUT and 36 BRAM,
  scaling with the ways. That is about 185.5 k placed, which is a report, not a key.
- Misses: about halfway between the 32 KiB and 64 KiB readings, roughly -3 % of mcf's L1D misses. The model has no
  12-way point, so this is an interpolation.

**Keys.** The E2 keys above. A routing failure or a WNS outside the band of -15.077 is a NEGATIVE result: collected,
labelled, no reruns.

## The model on gcc train01 and perl makerand (added before the A/B; perf/dcm-native/full/)

The stages are the board's own: Capstone arm-C stages-evict, identical to board-evict; riscv-base rv-fair3
(natstage/j-b3.list). All four runs ended rc 0 with specdiff PASS. Misses:

| | L1D 32 KiB | 64 KiB | DTLB 16 | DTLB 32 | DTLB 64 |
|---|---|---|---|---|---|
| Capstone gcc train01 | 332 M | 299 M (-10 %) | 222 M | 96 M | 32 M (-86 %) |
| riscv-base gcc train01 | 246 M | 221 M | 200 M | 78 M | 22 M |
| Capstone perl makerand | 19 k | 16 k | 36.0 M | 11.5 k | 566 |

**Predicted, with the per-miss penalty assumed (DTLB walk 15-30 cycles, L1D miss ~20 cycles):**
- DTLB 64: gcc 4-8 %, perl 5-10 %, mcf 4-8 %.
- L1D 64 KiB: gcc ~1 %, perl 0, mcf ~2.5 %.

**Caveats.**
- The riscv-base perl line also counts the harness's copy of the input tree and the hashing of 558 outputs, so it is
  not comparable with the Capstone arm and is not used.
- Capstone perl's near-zero L1D misses fit makerand's data fitting in 32 KiB, and its DTLB curve fits a page set just
  over 16 pages. Both are inferences; no second instrument checked them.
- The base run's HPM counters pin the penalties.

## RETRACTION (2026-11-13): the DTLB predictions above overcount; the silicon count is the bound

**The silicon reading.** The SPEC lane's first HPM read: perl makerand on the base, board 1, in-domain CSRUNV windows.
Event 4 (DTLB miss) reads 4.27 M walks, where the model above says ~36 M at 16 entries.

**What event 4 counts (read at 5f41c486e):**
- There is no shared or second-level TLB (`UseSharedTlb = 0`).
- Event 4 pulses once per data-side page walk started by the PTW (`cva6_shared_tlb.sv:248-255`, `cva6_ptw.sv:372`).
- The hardware DTLB holds superpages (`cva6_tlb.sv`, `is_page` per level). The model is 4 KiB pages only, so wherever
  the program is mapped with 2 MiB pages it counts walks that never happen.

**Withdrawn:** the DTLB-64 cycle predictions above (perl 5-10 %, gcc 4-8 %, mcf 4-8 %).

**What stands:**
- The ceiling is the silicon walk count x 15-30 cycles: for perl, <= 0.7-1.3 % of in-domain cycles. gcc and mcf
  ceilings follow from their event-4 reads.
- The model's L1D figures are unaffected: the page size does not enter the L1D model. The DTLB 64 build is still
  built and A/B'd, and its value is now expected to be small.
- What would have caught it: checking the model's 4 KiB-page assumption against how the native route maps memory,
  before converting misses into cycles.
