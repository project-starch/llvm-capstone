## The grade

**v1 stopped before any key** (`twc/b5b3/post-full.log`: grade_full rc 2, "NO DATA: router effective congestion
level"), so the CSMINT orchestrator armed on it booked nothing, as designed. The cause was two instrument gaps in my
grader, not data from the build:
1. **The router's congestion line.** Vivado prints "Effective congestion level" only inside a "Reporting congestion
   hotspots" block, which it emits only when it finds congested clusters. R-75 (d)'s log has the block (level 5); this
   build's router ran Phase 2 and printed none. grade_full.py treats the absent line as no data.
2. **WNS.** The lane's WNS key is one-sided ("outside on the good side: reported, not graded"). v1 carried
   grade_full.py's two-sided ±3.74 key, which would have failed this build for being FASTER.

**v2** (`twc/b5b3/grade-b5b3-full2.py`) applies the keys as pre-registered. It loads grade_full.py's readings
unchanged except for that one need(), which is relaxed by an asserted text patch.
- An absent router line reads "no hotspot reported" only if the new log's router Phase 2 ran, the new log has no
  hotspot block, and the reference log has one (the report's control).
- WNS is graded one-sided.
- v2 was negative-tested before the reading:
  - R-75 (d) graded as the new build fails on LUT, with WNS in band;
  - a reference without a hotspot block, the wrong reference (bitstream 1), a dead TIMING-23 control: each an ERROR;
  - a timing summary edited to WNS -19.000: FAIL on the bad side.
