# Plan v5: the kernel enters and leaves a protected program through ordinary traps

Status: draft of 2026-11-13, v5. It carries plan v4 forward with the decisions that the project lead took on 2026-11-13 after the reviews of the system-call design and of the mapping block M. Research only, nothing built. It implements [the kernel as the outermost allocator](../design/virtual-capstone/address-space-root.md) ("Entering and leaving the kernel", "Mappings", "Supervisor references") on top of the format alignment (block A). Where this plan and the design note differ (system-call buffers, the mapping block M, the code reference), the plan records the later decision, and the note follows when the steps land. A final review by three reviewers against the code of that day happens right before block B starts.

Repositories: **ASR** llvm-capstone-address-space-root, **NL** llvm-capstone-native-dev (contains native/linux-task-integration), **Q** capstone-qemu-address-space-root, **FW** caplifive-opensbi-address-space-root, **L** p13 `~/crenew-step4/linux`. `rv/` stands for `capstone/runtime/virtual/`. ASR is cited by function, because its line numbers move with every stage.

**Changes from v4.**
- System calls follow the reviewed design B3 with S1. Inside the kernel a user pointer is a handle: the 38-bit address and, in the upper bits, the number of its saved reference. A new processor rule checks every access that the kernel makes through a reference, as it checks the program's own. Plain accesses of S no longer reach the pages of a protected address space. This replaces v4's decisions 4 and 7, the libc's copies through the shared region, the direct path and every kernel-checked window. Step 5 is rewritten.
- One designated register keeps its tag across traps from S, in a 16-byte slot of the S trap frame. This replaces v4's rule that no kernel register holds a capability across an instruction that can trap, and it changes the debug sentinel (step 3).
- Step 1 gains the two QEMU rules. It loses the linear-map path for the signal frame, which bypassed the processor's check.
- The firmware also refuses to emulate a misaligned S access through a reference (step 2).
- Steps 8 and 9 lose their windows: the futex word, the exit word and the signal frame become ordinary accesses through a reference.
- Mappings have no kernel-private block M. Each region is a depth-1 child of R, and step 6 copies the mapping code as it will be after the adapter stage that removes M.
- Swap of pages with few references becomes a late step (step 10). End to end moves to step 11.
- `fork` is recorded as a design and stays unbuilt.
- A page that two address spaces share carries no references.
- If the processor rule slips, the same binding runs with v4's kernel-checked window.
- The estimate rises to about 90 to 135 days.
- NL's image grant is at `binfmt-dom.h:450` (v4 said `:455`).

## 1. Target state

**Protected U and the root.** Under a new QEMU property, U is protected exactly when srevroot is nonzero, and it uses the table that srevroot names. Today the test CSR scapctl decides (Q `target/riscv/csr.c:4185-4202`), which the RTL lacks (ASR `capstone/docs/ref/ISSUES.md:2254-2263`). S already uses the table on that condition (Q `capstone_table.c:188`), and S data accesses stay plain whatever srevroot holds (`translate.c:142-151`) until step 1. QEMU recomputes the protected flag on every srevroot write (`cpu_helper.c:163-164`), and the write drops the lifetime caches (`csr.c:4228-4234`).

`exec_mmap` calls `activate_mm` before the table exists (L `fs/exec.c:1024`), so the loader writes srevroot itself once it has created the table. `switch_mm` writes it for every other switch (`arch/riscv/mm/context.c:305-323`): the mm's table, or 0. It returns early when `prev == next` (`:309`), which is harmless. In S the task's own table stays selected, so `select_root` writes srevroot only when it selects another table, and `restore_root` writes back the value it found. NL's R-58 rule (`capstone_vm.c:1429-1446`, `:1512-1516`) writes 0 instead, because the CSRUNV switcher left S in a context's table and the CPMP trackers of the physical profile flushed only on a namespace edge (ISSUES S-23, R-58). The CSRUNV route keeps that rule until step 11. On the RTL the trap route needs either the semantics owner's fix of 2026-10-20 (the CPMP trackers act only on physical broadcasts) or a retired physical profile. This is checked before block B reaches the RTL.

**The guard on return to U.** Every return to U reaches `resume_userspace` (L `entry.S:266`) through `ret_from_exception` (`:251`): from `ret_from_syscall` (`:233`), `ret_from_fork` (`:520`), `ret_from_kernel_thread` (`:527`, which covers `kernel_execve`), `work_pending` (`:373`), signal delivery through `do_notify_resume` (`:381`) and `handle_syscall_trace_exit` (`:403`). Only SPP = 1 goes to `resume_kernel` (`:264`). Interrupts stay off from `:253` to `sret`. The guard sits after the work check (`:270`) and before `csrw CSR_SCRATCH, tp` (`:284`). It compares srevroot with the expected value (the table of `current->mm` for a protected mm, 0 otherwise) and also checks that `TIF_CAPSTONE` agrees with the mm's protected flag. On a mismatch it calls a C function that writes 0 to srevroot, raises SIGKILL and returns to the work loop, so the task never reaches U and exits through `do_exit`. Asm-offsets supply the field of `mm->context`.

**Program counter.** The program counter is a plain address, and no capability covers the code. A fetch passes the page table and nothing else. The kernel maps only the text of the program image executable and refuses `PROT_EXEC` on mapping blocks, the shared region, stacks, grants and metadata. The image block carries the kernel-owned flag, which refuses `munmap`, `mremap` and `mprotect` (section Mappings): the image's data reference covers the whole image, so the page's W bit alone keeps stores out of the text. Compiled code needs no code capability: the virtual build uses `-capstone-gp-free -capstone-image-gp` (`VirtualCodegen.cmake:28`), jumps are plain `jal` and `jalr`, globals come from SCC on the launch gp (`CapstoneISelDAGToDAG.cpp:95-125`), and the runtime's `start.S` and `setjmp.S:84-90`, `:110` jump plainly. QEMU derives gp from `pc_cap` only in virtual C (`op_helper.c:896`, `:928`, `:4202`) and checks U fetches against it only there (`translate.c:1525`). Leftovers that change in step 4: the image grant `dom_grant(..., 3, 7, base+entry, text)` (NL `binfmt-dom.h:450`) and the check in `add()` that the cursor lies inside the text prefix (NL `capstone_vm.c:1681-1683`). In step 9 the virtual branch of `altstack.S` changes, and in step 11 the tests that execute through a mapping's code capability (`contract.c:87-99`).

**Register slots.** `struct pt_regs` (L `ptrace.h:15-54`) stays the integer view that C code reads. Each task gets 31 16-byte slots in `thread_info` (`thread_info.h:58-69`), within a 12-bit offset of tp. `task_struct` is cache-aligned (`fork.c:904`). Kernel code that changes a user register sets its slot through one of two helpers. The integer helper writes pt_regs and both doublewords of the slot with plain stores, and a plain store clears the granule's tag (NL `rv/module/capstone_vm.c:1517-1520`). The reference helper copies a kernel slot into the user slot with LDC and STC in one run and writes the address into pt_regs. The adapter's result writer, exec, clone, mapping results, signal delivery and the restart conversions use the helpers. The loader writes all 31 slots at exec. `arch_release_task_struct` (`fork.c:162`, called by `free_task` at `:556`) clears the slots, which covers normal exit and the clone error path (`fork.c:2547-2551`, `:1941-1947`).

**Syscall restart.** Until step 9 admits restart, the result writer turns every ERESTART code into EINTR, as the providers of the first backend do today (NL `native-syscall-dom.h:130`, `:306`, `:552`, `:624`, `native-files-dom.h:21,54`, `native-gcc-dom.h:55,180`, `native-time-dom.h:55-62`). Once restart is admitted, the adapter leaves slot a0 untouched for ERESTARTSYS, ERESTARTNOINTR and ERESTARTNOHAND, and Linux sets a0 back to `orig_a0` (L `signal.c:297`). The restarted call passes the binder again and gets fresh handles from the slots, so no handle outlives its call. Where `handle_signal` writes `-EINTR` (`signal.c:250`), a protected task goes through the integer helper, so slot a0 holds the error and not the original argument reference. ERESTART_RESTARTBLOCK stays EINTR, because Linux would write a number into a7 (`:301-302`), which carries the selector. So the futex restart block, which keeps a user address beyond its call, never runs.

**Entry from U, instruction by instruction.** While U runs, sscratch holds the task pointer as an integer. While S runs, sscratch holds 0.

1. `csrrw tp, sscratch, tp` (L `entry.S:18`), then `bnez tp, _save_user`. A trap from S falls into `_restore_kernel_tpsp` and the stock `_save_context` (`:29`), which stores integers only and touches no user slot. Stock code reaches `_save_context` from both origins. The plan gives the U origin its own label and tail.
2. `_save_user`: `STC sp, SLOT(2)(tp)` and `REG_S sp, TASK_TI_USER_SP(tp)` (stock `:30`).
3. `REG_L sp, TASK_TI_KERNEL_SP(tp)` and the frame allocation.
4. For x1, x3 and x5 to x31: `REG_S xN, PT_xN(sp)` and `STC xN, SLOT(N)(tp)`.
5. `csrrw s5, sscratch, x0` moves the tagged user tp out and leaves 0 (replacing stock `:90` and `:102`). Then `REG_S s5, PT_TP(sp)` and `STC s5, SLOT(4)(tp)`.
6. Clear: every user register that still holds a value is overwritten with an integer (an integer write clears the tag), except tp, sp and the registers the common tail sets next. STC copies a reference, so without this step user references would stay in kernel registers.
7. Jump to the common part of `_save_context` after its register stores (status, epc, badaddr, cause), which both tails share.

The trap clears SIE, and steps 1 to 6 store only into the task's own `thread_info` and kernel stack, which are mapped and 16-byte aligned. No S trap can occur in this window. An M trap can occur at any instruction, and the firmware of step 2 keeps every register tag and never touches sscratch.

**Exit to U.** After the guard, `csrw CSR_SCRATCH, tp` (`:284`), status and epc as today (`:297-319`). Then a protected task branches to `restore_user`: `LDC xN, SLOT(N)(tp)` for x1, x3 and x5 to x31, `LDC sp, SLOT(2)(tp)`, and last `LDC tp, SLOT(4)(tp)`, then `sret`. `resume_kernel` and `restore_all` (`:363-368`) keep the integer loads for S returns and for ordinary tasks, apart from the designated register below. The branch to `restore_user` exists only on the U path, so a nested S trap of a protected task never loads user slots. The program never sees a handle, since the exit loads the slots and not pt_regs.

**References in kernel registers.** Traps from S save registers as integers, with one exception. The routines for user memory hold a program reference in one designated register, t6, across an access that can page-fault and sleep. The S tail of `_save_context` therefore stores t6 with STC into a 16-byte slot of the frame it allocates, and `restore_all` loads it back with LDC on a return to S. A nested S trap gets its own frame and so its own slot. This replaces v4's rule that no capability sits in a kernel register across an instruction that can trap. t6 holds a reference only inside one assembly routine or one inline-assembly block, which clears it before it ends, so the C compiler never spills it. Every other run executes with interrupts off and contains only LDC and STC on kernel slots, LCC, CINCOFFSET, CDERIVE after the record margin is ensured and CREVOKE after the request check accepted the operand. Each run clears its registers at its end. A debug option checks every register with LCC selector 1, which never faults, on each trap from S. It stops the kernel on a tagged register other than t6, and on a tagged t6 whose sepc lies outside the routines for user memory.

**Check at the access.** The kernel touches the program's memory only through a reference, and the processor checks that access as it checks the program's own. Under the property, a load, store, AMO, LR/SC, LDC or STC in S whose base register holds a reference passes the same checks as in U: tag, bounds and lifetime against the table that srevroot names. A stale or out-of-bounds access raises its cause in S (25 for a stale lifetime, 28 for bounds), and the kernel's exception table turns it into EFAULT (section Faults). A page fault during such an access is an ordinary page fault. Linux resolves it and may sleep, the instruction runs again, and the processor checks the reference again at the retry. A CREVOKE, or a `munmap` followed by an `mmap` at the same address while the call sleeps, therefore makes the access fail. No window, fault loop or hold is needed. Today QEMU treats a tagged base in S as a plain address: `disas_context_cap_data` excludes S (Q `translate.c:150`), and `trans_csldc` (`insn_trans/trans_capstone.c.inc:282`) and `trans_csstc` (`:406`) take only a plain base in S (`plain_base_refs`, `:271`).

Hardening. For a protected address space, SUM does not open user pages to plain addresses. While srevroot is nonzero, a plain load or store of S to a user page faults whatever SUM says, plain-base LDC and STC included. Today SUM alone picks `MMUIdx_S_SUM` (Q `cpu_helper.c:69-70`). A kernel path that nobody ported then fails with EFAULT instead of bypassing the check. The kernel's own memory, the linear map included, stays reachable by plain address.

**System calls.** The reviewed design is B3 with S1: a handle binds each user pointer to its saved reference, and the processor checks each access (three reviewers, 2026-11-13).

Bind. The libc's stub keeps its register layout: arguments in a0 to a5, references or integers, the Linux number in a6 and a selector in a7 (NL `native-syscall.S:14-27`). The libc no longer copies buffers into the shared region, and it converts only the two structures with opaque values (below). For a task with `TIF_CAPSTONE`, `handle_syscall` (`entry.S:169-235`) calls a binder before the `sys_call_table` entry of the number in a6. A protected mm without `TIF_CAPSTONE` is refused (the guard and the dispatch check the same pair). The binder looks the call up in an allow-list of about 100 calls and refuses every other call with ENOSYS. For each pointer position it writes a handle into the integer view of pt_regs: the address in bits 37 to 0, zero in bits 39 and 38, and above them the number of the saved reference. Numbers 1 to 6 name the slots of a0 to a5, which already hold the tagged arguments. An untagged value in a pointer position gets number 0, which names no reference, so an access through it fails. Integer positions pass unchanged. A table generated from the `SYSCALL_DEFINE` types gives the pointer positions. The allow-list adds the positions those types miss: the address arguments of the mmap family, which Linux declares as `unsigned long`, and the arguments whose meaning depends on a command or an operation (`ioctl`, `fcntl`, `prctl`, `futex`). A command outside the allow-list is refused, so no integer position reaches a routine for user memory. A handle used as a plain address is not canonical in Sv39 and faults.

Embedded references. A compat-style loader serves the calls whose structures hold pointers: iovec (`readv`, `writev`, `preadv`, `pwritev`), msghdr and mmsghdr (`sendmsg`, `recvmsg`, `sendmmsg`, `recvmmsg`, with the write-back of lengths and flags), argv and envp (`execve`), the sigset pack of `pselect6`, and `stack_t` of `sigaltstack` (step 9). It reads the user layout, with 16-byte pointers, through the outer reference. It loads each embedded reference with its tag by LDC through that reference into a per-call list, and writes the kernel layout with handles whose numbers start at 7. An untagged embedded pointer gets 0. The kernel clears the list at the end of the call, so a handle is valid only during its call. Signal delivery and the exit path, which run outside a call, put the reference they hold into the list and use a handle in the same way.

Check. For a protected task, the routines for user memory access through the reference that the handle names: `__asm_copy_to_user` and `__asm_copy_from_user` (L `arch/riscv/lib/uaccess.S`), `__get_user`, `__put_user`, `__clear_user`, `strncpy_from_user`, `strnlen_user` and the futex atomics. Each refuses a handle with a guard bit set or a number outside the call's list (EFAULT). A carry out of the address therefore never selects another reference. Each loads the reference into t6 with LDC, sets its address, accesses through it and clears t6. The copy routines keep Linux's residual counts, so a short transfer or a fault part way returns the bytes copied. The string routines read byte by byte near the end of an object, so a string that ends in the object's last byte passes. No routine issues a misaligned access through a reference: it splits the access into bytes. `access_ok` strips the handle and checks only the address range, as stock Linux does, because `vfs_read` calls it with the declared count, which may exceed the object when the transfer is short. RISC-V's `untagged_addr` strips the handle, which covers the sites where Linux already untags arm64's tagged addresses. An audit covers the remaining address-keyed sites (about 30 by one reviewer's count): futex keys, `find_vma`, the mmap family, null tests and address comparisons.

Opaque values. The kernel returns `epoll_data` and `sigval` as 64-bit integers, so a reference in them would come back untagged. The libc keeps each such value in a side table, passes the table's index to the kernel, and puts the 16-byte value back when it returns: `epoll_wait` in step 5, the handler's `si_value` in step 9. Today `dl_epoll_ctl` and `dl_epoll_pwait` (NL `ports/musl-capstone/runtime/delegate.c`) carry `data.u64` without a tag.

Stored pointers. The kernel keeps a user pointer that outlives its call as a full 16-byte reference, or it refuses the call. It keeps the exit word (section Thread exit) and the alternate signal stack (step 9). It refuses `set_robust_list`, `rseq` and aio, and restart blocks never run (section Syscall restart).

The shared region (the exchange and metadata grants, `binfmt-dom.h:452-453`) carries no buffers any more. It stays while some path still uses it, and step 11 removes what none uses.

**Fallback: the kernel-checked window.** If the processor rule of step 1 slips, in QEMU or later on the RTL, the binding stays and the check falls back to v4's window. The routine for user memory loads the slot that the handle names, reads bounds and id with LCC, reads the generation from T, clears the register, and accesses by plain address with interrupts, preemption and page faults off. On `-EFAULT` it leaves the window, resolves the fault and checks again from scratch, as NL's checked copy does (`checked-copy-dom.h:236-300`, with a hold of the mapping's pages and range, `:162-207`). The fault-in must not touch the buffer unchecked. The futex word, the exit word and the signal frame then need windows again, as in v4's steps 8 and 9. The hardening must stay off under the fallback, because the window accesses by plain user address. An unported path then bypasses the check silently. The window must also read a generation that agrees with the processor's lifetime cache. One reviewer found no evidence that CREVOKE writes records through to memory. `cv_copy_check` uses CSCHECK, which only the CSRUNV route has, so the fallback needs a check without it.

**Faults.** Linux resolves page faults, and tags follow physical pages (NL `rv/unpinned/linux-6.1-unpinned.patch:3-34`). The firmware delegates causes 24 to 30 (Q `cpu_bits.h:699-705`). From U, the kernel turns 24 to 29 into SIGSEGV with the native fault line (`binfmt-dom.h:314-322`). For 30, which protected U raises on an exhausted table (`op_helper.c:1273-1274`), the kernel grows the table and retries. From S, the handlers for 24 to 30 call `fixup_exception`, and the routine returns EFAULT or its residual count. An S fault without an exception-table entry stops the kernel. A reference fault never reaches the page-fault handler, since paging cannot repair a stale lifetime or a bound. `fault_in_readable` and `fault_in_writeable` already use the routines for user memory and so access through the reference. `fault_in_user_writeable`, which the futex loops call after an EFAULT, resolves the page by address. For a protected task it becomes an atomic add of 0 through the reference, so a stale word fails there too and the loop ends with EFAULT. A slot whose generation reaches its last value is retired, never reused (block A, F2).

**Mappings.** Each region of a protected program is a block of depth 1, a child of R: the image, the stack, each `mmap`, and the shared region while it remains. The kernel keeps no private block M per mapping. It accepts a request with a reference if and only if the reference is tagged, live and of depth exactly 1, and its bounds cover the named pages, which lie inside one block. A `munmap` that removes the last mapped pages of the block, a call that names the whole block included, executes CREVOKE on that reference before Linux removes the pages. A `munmap` that leaves mapped pages removes those pages and ends no lifetime. The refill rule of the adapter's stage 4f holds with the passed reference in the place of P: a refill happens only while the record after the reference's is not deeper. `mremap` gives an address range to another mapping only after it has released the block that covered it. A kernel-owned flag refuses `munmap`, `mremap` and `mprotect` on the image, the startup block, the main stack and the shared region. The check and the CREVOKE run with preemption off after `mmap_write_lock`, so no thread of the program runs between them on one hart. The CREVOKE has an exception-table entry, and a CREVOKE that faults refuses the request before anything changes. Only teardown and the rollback of a failed `mmap` end a block without a request. A program that renews a narrowed reference ends the block only by removing its last mapped pages, and a program that revokes its block itself can no longer end it. Then the range stays reserved until exit. That is a leak in a faulty program, not a safety problem.

A page that two address spaces share carries no references. Today the kernel refuses such mappings: it accepts only anonymous private mappings. Later a page attribute can make a tagged store to such a page lose its tag.

**Loader, module and lifetimes.** The native loader execs a `.dom` image without launcher (`binfmt-dom.h:382-502`). It sets the protected flag on `bprm->mm` before `begin_new_exec` (`fs/exec.c:1376`). The mm becomes visible only at `exec_mmap` (`:180`, `:1294`), and `exec_update_lock` is taken at `:991` and dropped in `setup_new_exec` (`:1447`), so no opener of `/proc/PID/mem` sees the new mm unprotected. It then creates the table with `context_create` (`capstone_vm.c:3071-3140`), stops attaching a CSRUNV step (`binfmt-dom.h:485`), derives the blocks as depth-1 children of R, writes the slots and srevroot, and returns through the ordinary path. It finishes its plain writes into the program's pages before it writes srevroot, since the hardening refuses them afterwards: the image tail (`binfmt-dom.h:436`), the startup block (`:446`) and the signal block (`dom_store`). The `resume_userspace` hook and `riscv_capstone_run_user` go (`rv/kernel-native-task.patch:197-240`). The module stays built in (`rv/install-native-task.sh:44-47`). Process resources still go before `exit_mm` (`kernel-native-task.patch:302-309`).

Teardown of the table, R and the blocks runs in `arch_exit_mmap`, in process context under `mmap_read_lock` (L `mm/mmap.c:3071`), and writes 0 to srevroot if the dying table is selected. `destroy_context` frees only non-sleeping residue. `__mmdrop` calls it (`fork.c:786`), often from `finish_task_switch` through `mmdrop_sched` with preemption off (`sched/core.c:5113`, `include/linux/sched/mm.h:76-78`). RISC-V does not define it (`arch/riscv/include/asm/mmu_context.h:19,26,38`), so the patch adds `#define destroy_context` before the include of `asm-generic/mmu_context.h` (`:45`). Both handle a context that an exec failure left half built (the mark set, the table absent or partial). A kernel thread that borrows a protected mm holds `mm_count` (`sched/core.c:5176-5181`) and runs only in S. `kthread_use_mm` (`kthread.c:1405-1423`) refuses a protected mm.

**Refused paths and scope.** `mm_access` refuses a protected mm before its `mm == current->mm` shortcut (`fork.c:1396-1405`), which covers `/proc/*/mem` (`fs/proc/base.c:802` through `proc_mem_open`), `process_vm_*` (`mm/process_vm_access.c:202`), `base.c:2158` and `madvise.c:1478`. The other `get_task_mm` users in fs/proc read only. ptrace stays refused. Every path that pins user pages and accesses them through the kernel's map is refused for a protected process: O_DIRECT, `vmsplice`, `io_uring` and the GUP users above. perf skips user registers and the user stack of a protected task (`kernel/events/core.c:6645`, `:6724`), and protected tasks are not dumpable. The loader maps no vDSO (`arch/riscv/kernel/vdso.c:310`). Robust lists and rseq, which Linux writes at exit (`fork.c:1468-1478`), are refused, and the exit word is kept as a full reference. Out of scope: more than one hart, the vDSO and dynamic code. `fork` is a design only (below), and swap comes late (step 10).

**Thread exit.** Without a store at every exit, a join on a thread killed by a signal would never return. The kernel keeps a thread's exit word as a full 16-byte reference in the task, set at clone (`CLONE_CHILD_CLEARTID`) or by `set_tid_address`, beside `clear_child_tid`, which holds the stripped address. Linux's exit path (`mm_release`, `fork.c:1468-1478`) runs for every exit, death by a signal included. It stores 0 through the reference with an ordinary checked access and wakes the futex at the stripped address. If the word is stale or out of bounds, the store fails and Linux drops it, as it drops a `clear_child_tid` store that faults.

**Signals.** RISC-V Linux has no `SA_RESTORER` (`asm-generic/signal-defs.h:53` names it only in a comment): `setup_rt_frame` (`signal.c:179-235`) sets `ra` to the vDSO's `rt_sigreturn` (`:202-203`), which a protected task does not have. For a task with `TIF_CAPSTONE`, `setup_rt_frame` takes its own branch at its top (`:185`):
- **Restorer.** The adapter takes a selector that registers one restorer address per mm, accepted only inside the image text. The restorer sets a6 and a7 per the selector protocol before its ecall. The kernel refuses to install a handler (other than SIG_DFL and SIG_IGN) before a restorer is registered.
- **Frame.** The frame lies below the saved sp reference (or the alternate stack, below). It holds the standard `rt_sigframe` (siginfo, ucontext with the integer registers) followed by an aligned area of 31 16-byte slots. The kernel writes the slots with STC through the reference and the integer fields with ordinary stores through it, so the processor checks every store. A page fault inside is an ordinary fault of a routine for user memory.
- **Handler registers.** epc is the handler (an integer), ra the restorer (an integer, through the integer helper), a0 the signal number (integer). sp, a1 (`&frame->info`) and a2 (`&frame->uc`) are references: CINCOFFSET of the saved sp reference (or of the alternate-stack reference) to the address, written through the reference helper, so the handler's stack and argument accesses pass bounds and lifetime checks.
- **Alternate stack.** `sigaltstack` takes `stack_t` through the compat loader, and the kernel keeps `ss_sp` as a full reference per thread, checked at each access. `sigsp()` (`:171`) no longer takes an integer for a protected task.
- **sigreturn.** It reads the frame through the saved sp reference with ordinary checked loads. A slot is restored only if its address equals the integer field of the same register in the frame. Otherwise the register becomes the integer from the frame, untagged. A frame that fails the check kills the task. Nested signals stack frames as usual.
- **sigval.** The libc's side table carries a `sigval` that holds a reference (`timer_create`, `sigqueue`, `mq_notify`), and the handler's wrapper puts the reference into `si_value`.
- **libc.** musl-capstone's `signals.c` (about 470 lines) and the virtual branch of `altstack.S` change with the frame format.

**Swap.** While a page is out, the kernel keeps the page's references in its own memory and moves them back at swap-in. It moves each with the existing raw moves (LDC and STC with a plain kernel base, 16 bytes per reference), so no instruction makes a reference from numbers. The kernel swaps out only pages with few references, at most about one eighth of the granules (32 of a page's 256). Other tagged pages stay resident, as every tagged page does today. Linux 6.1 declares the hooks in `include/linux/pgtable.h` (`arch_prepare_to_swap`, `arch_swap_restore`, `arch_swap_invalidate_page`, `arch_swap_invalidate_area`), and arm64 uses them for its memory tags. T stays resident, so a reference whose object the program released while its page was out is stale after swap-in. A swapped page costs at most 32 references and their offsets in resident kernel memory, about 512 bytes plus an index.

**`fork`, as a design only.** `fork` stays unbuilt, and posix_spawn covers the programs. In the design the child gets a copy of the table with the same slots and generations, since the processor writes the table through physical addresses and copy-on-write does not cover it. The copy is one snapshot. The kernel forces the record cache to write back and holds the program's other threads off until the table and the memory are copied, so no lifetime ends in one copy and not in the other. No memory shared between the two address spaces holds references (section Mappings). The copy costs 16 bytes per slot of the table's high-water mark.

## 2. Decisions of the project lead (2026-11-13)

1. Protected U when srevroot is nonzero, behind a property, with a guard on return that checks both directions.
2. sscratch and mscratch keep tags under the property. A swap moves the whole register, and a write from an integer clears the tag.
3. No code reference. The program counter is a plain address, and the page's X bit alone decides execution. The kernel maps only the image text executable.
4. Bind (B3, replaces v4's decision that the libc's selector ABI with its copies stays). Inside the kernel a user pointer is the 38-bit address plus the number of its saved reference in the upper bits. Only the entry code creates these handles, with pointer positions from the `SYSCALL_DEFINE` types and number 0 for an untagged value, plus a compat-style loader that reads iovec, msghdr and argv in the user layout through the outer reference and loads each embedded reference with its tag into a per-call list.
5. Futex comes with threads, checked and read in one step, with a race test. Under decision 7 the processor's check at the read is that step.
6. One tag-keeping OpenSBI entry serves protected processes. The legacy monitor stays only for the CSRUNV route until its removal. QEMU picks the entry by the protected flag (`cpu_helper.c:1953-1954`).
7. Check (S1, replaces v4's decision of checked copies first and plain copies of the kernel region later). A load, store, AMO, LR/SC, LDC or STC through a reference in S passes the same checks as in U against the table in srevroot. The routines for user memory load the slot, set the address and access through it. A stale or out-of-bounds access takes the exception table and yields EFAULT. For a protected address space SUM does not open user pages to plain addresses. If the processor rule slips, the same binding runs with v4's kernel-checked window.
8. Mappings without M. Each region is a depth-1 child of R. A request is accepted if and only if its reference is tagged, live and of depth exactly 1 and its bounds cover the named pages. A `munmap` that removes the block's last mapped pages (a whole-block call included) executes CREVOKE before the pages go, any other `munmap` ends no lifetime, `mremap` gives an address only after releasing the covering block, and kernel-owned blocks are flagged against `munmap`, `mremap` and `mprotect`.
9. Swap is a late step, for pages with few references, whose references the kernel keeps in its own memory while the page is out.
10. `fork` is a design only. posix_spawn covers the programs.
11. A page that two address spaces share carries no references.
12. One hart stays.

## 3. Steps

1. **QEMU rules.** The protected flag from srevroot and tagged sscratch and mscratch. Two new rules under the property. First, in S a load, store, AMO, LR/SC, LDC or STC whose base register holds a reference passes the checks of U against the table that srevroot names (today S excludes it, `translate.c:150`, `trans_capstone.c.inc:271`). Second, while srevroot is nonzero a plain access of S to a user page faults whatever SUM says (`cpu_helper.c:69-70`). QEMU tests the base register's tag on S memory operations only when a translation-block flag says that srevroot is nonzero. Test: a bare-metal S runs the entry and exit of section 1 for two protected programs and one ordinary program. References survive an ecall, an S timer interrupt, a page fault and a nested S trap during a system call. B's use of A's reference faults 25. U cannot write srevroot, cannot use a plain-base LDC and reaches no kernel address through R. A fetch from a non-executable page faults with the page-table cause. In S, a load, a store, an AMO, an LR/SC pair, an LDC and an STC through a live reference to a user page pass, and the STC keeps its tag. Through a stale reference each faults 25 in S, and past the bounds 28. A plain S load of a user page faults with SUM set while srevroot is nonzero, and passes when it is 0. Without the first rule the S access through a stale reference passes (must FAIL). Without the second rule the plain S load reads the protected page (must FAIL). 5 to 7 days.

## 5. Estimate and riskiest steps

The step ranges sum to 83 to 120 working days for one person. With a contingency of about a tenth, the plan budgets about 90 to 135 days after block A, against 65 to 90 in v4. Step 5 accounts for most of the rise and swap for 5 to 8 days, while steps 8 and 9 give back a few days with their windows. A first program exits with its status after step 4, near day 25. Single-threaded programs run end to end after step 7, near day 55 to 75. The RTL work is extra, and it now includes the processor rule and the hardening.

Nothing is measured, and the reviewers' estimates of B3 with S1 differ. One reviewer put the work at 35 to 45 days, three to four times what finishing the libc's copies would cost, since that code exists in NL. Another put it at about 800 to 1,200 kernel lines plus about 30 lines of QEMU and RTL, below the cost of the copies, but counted those copies as new code for about 100 calls. The third gave no number and said that the change is not small without a measured implementation. This plan's B3 work (step 5, the additions to steps 1 to 3, less the windows of steps 8 and 9) comes to about 25 to 37 days. They also differ on the processor rule: about 20 lines in QEMU's translator and one multiplexer in the RTL, or a tag test per S memory operation behind a translation-block flag, or changes to the RTL's memory pipeline, fault classification, atomics, table access and trap state.

The riskiest steps are 5, 3 and 1. Step 5 is the largest. It audits about 100 calls for embedded pointers, command-dependent arguments and address-keyed sites. The hardening turns a miss into EFAULT instead of a bypass, so a miss costs completeness and not soundness, but each miss costs a debugging round. In step 3 a mistake stays silent: a missed helper call returns an integer where a reference belongs, and the program faults much later. The tagged t6 across S traps adds a second place for such a mistake, and the debug sentinel, the clearing control and the t6 control exist to catch it early. Step 1 adds a check to every S memory operation of a protected program. If that rule slips, the fallback brings back v4's windows and turns the hardening off. Step 8 stays risky: the native lane has never admitted a second thread of one mm (`checked-copy-dom.h:3-5`, `native-syscall-dom.h:37-46`, `kernel-native-task.patch:262-264`), and a generic futex patch joins the adapter. Step 6 carries estimate risk, because the two module versions diverged widely and the stage that removes M is not yet written.

## 6. Risks

**Performance.** The entry adds 31 STC and the clearing step, the exit replaces 31 integer loads by 31 LDC, and the guard adds about six instructions. Ordinary Linux takes 601 attempted instructions for getpid, the old ioctl loop 609 and the CSRUNV task return 1,345 (NL `rv/tests/native-task/README.md:872`, `:893-895`). The new entry should land near ordinary Linux plus about 70 instructions before dispatch, plus a few instructions per pointer argument in the binder, to be measured in step 11. Each S trap adds one STC and one LDC for t6. The data moves once, as in stock Linux, where the libc's copies moved it twice. The string routines read the last bytes of an object one at a time. In QEMU each S memory operation of a protected program pays a tag test. srevroot changes only at a switch and in the rare operation on another table, while today every kernel window writes it twice and every CSRUNV once. On the RTL each tagged access also touches tag memory, and every S access through a reference reads the lifetime table as a U access does.

**Firmware.** OpenSBI swaps tp through a scalar mscratch (FW `fw_base.S:589`). Until step 2 lands, every M trap strips the tags of a protected program, and with sstc off that includes every timer tick.

**RTL.** medeleg admits 24 to 30 since the Q-24 fix (`ISSUES.md:2307`). The RTL lacks protected U, supervisor references, tagged scratch CSRs, the check of S accesses through a reference and the hardening. The `restore_root` rule depends on S-23's tracker fix or a retired physical profile. So the kit runs on QEMU only.

**Remaining.** FP registers carry no tags (Q `cpu.h:152` against `:130`). Protected U refuses vector memory operations (Q `tests/trusted-linux-u-access/README.md:90`). `fork` stays unbuilt. A page with more than about 32 references never swaps. The long-release trap needs one more cause handler once QEMU raises it. A call or an ioctl command outside the allow-list and every pin-and-access path answer an error, so completeness holds for the allowed calls only.
