# C-64 and I-11 fixed in the musl-capstone runtime — predictions, then results (2026-09-25)

**The change** (all in the tree before any boot below):
- **`ports/musl-capstone/runtime/hostcall.c`, C-64:**
  - `domain_main` runs `.init_array` after the exit jump is armed, before `main`;
  - a strong `__libc_exit_fini` replaces musl's weak one;
  - each slot, a link address stored as an integer, is called through an anchor function's code
    capability moved by the link-address distance.
- **`hostcall.c`, I-11:** `hc_report_unserved` writes through the WRITE_STDOUT rounds directly
  (`hc_stdout_bytes`), not through the program's descriptors.
- **`my_first_domain/link.ld`:** priority sections (`SORT_BY_INIT_PRIORITY(.init_array.*)`, and
  the same for `.fini_array`) sit inside the markers, ahead of the plain sections.
- **tshark port:** its own copy (`src/tsapp-init-fini.c`, `domain_entry.c`'s call) is removed.
  Two strong `__libc_exit_fini` would clash, and the constructors would run twice.
- **New core tests:** `tests/runtime-qemu/init-fini/` and `unserved-report/`, each with a control
  linked against the hostcall.c of `7b10f5f86db5` (dev before the fix).

## Predictions (written before the first boot)

- **P1** `run-hostcall-init-fini-probe.sh`:
  - init-fini prints exactly what `ctors.c` prints natively: `CTOR p 1`, `CTOR a 2`, `CTOR b 3`,
    `MAIN 4`, `DTOR b 5`, `DTOR a 6`, `DTOR p 7`, then status 0 and no fault;
  - the control halts with cause 24.
  Refuted by: any other order or line, a fault, or a control that does not halt.
- **P2** `run-hostcall-unserved-report-probe.sh`: the fixed image prints
  `capstone-domain: UNSERVED syscalls: 160x2`, and the control prints no such line. Both return 0.
- **P3** `run-hostcall-exit-hook-probe.sh`: PASS as before, controls included. exit() now goes
  through the runtime's `__libc_exit_fini`, which with empty arrays does nothing.
- **P4** `run-hostcall-all.sh` (corpus-runner): every runner that passes on the unfixed tree
  passes. The two new ones pass, which is P1 and P2. Stalls are infrastructure, retried, never
  counted. These suites boot the shared rootfs, still ext4-corrupt.
- **P5** `ports/musl-capstone/libc-test/run-libc-test.sh`: the same verdict per test as the
  unfixed runtime. The last table, 43 PASS / 7 FAIL / 0 FAULT / 5 NOBUILD / 22 EXCLUDED
  (2026-09-17), is expected unless the compiler has moved a test since. If the counts differ, the
  unfixed runtime is run too, to attribute the difference.
- **P6** FFmpeg app `run-qemu.sh all` (level0): 30/30 as pre-registered for that port.
- **P7** tshark, on its own runner:
  - stages M1–M5: REACHED and output MATCH;
  - oracle: the same verdicts as `results/2026-09-24-qemu-tshark-staged`;
  - `tests/runtime-gaps/run.sh`: c64 → stdout MATCH, i11 → the runtime line present, c65 →
    HALTED as before (C-65 is not fixed).
- **P8** No image changes behaviour when it has empty arrays. Its code differs in `hostcall.o`
  only, which is expected and not tested beyond P3–P6.

## Amendment (before landing, after the audit, before the reruns)

An audit of the change found a real defect. The constructors ran before the program's
environment existed:
- entries set `__environ` inside `capstone_main`, which runs after the constructors;
- in C, environ exists before any constructor runs;
- GLib's constructor reads `G_DEBUG` and `G_MESSAGES_PREFIXED`, and would never have seen them.

Nothing faulted, and no test could see it, because the test's own entry had the same ordering.

Fixed:
- `hostcall.c` defines a weak default `__capstone_domain_environ()` (an empty environment,
  C-56-safe). `domain_main` sets `__environ` from it before running the constructors.
- The tshark entry moves its `/tmp/domain.env` reading into that hook.
- The audit also asked for a guard: `hc_stdout_bytes` returns -EIO while no region is shared.

Amended predictions:
- **P1 (amended):** init-fini's entry provides `INIT_FINI_ENV=before-main` through the hook, and
  its constructor `a` prints `getenv`'s value. The native reference runs with the same variable,
  so the expected output is `CTOR a 2 env=before-main`; any other value, `(unset)` included,
  refutes it. The control must also print `MAIN 1` first, meaning no constructor ran, and halt with
  cause 24.
- **P1 to P3, P6 and P7 are rerun** on the amended change.
- **P4 and P5** (corpus-runner, the libc-test pair) were already running on the first version. The
  amendment changes only when `__environ` is set before `main`, and every entry overwrites it in
  `capstone_main`. So their results carry over, and are reported as taken on the first version.

**Reruns on the amended version** (after the environment fix):
- init-fini: `CTOR a 2 env=before-main`, native order, status 0. The control prints `MAIN 1` and
  then halts with cause 24.
- unserved-report and exit-hook: PASS with their controls.
- tshark: stages REACHED and MATCH (`qemu-stages-20260925-061342-T5Wq`). Oracle B MATCH with the
  flips firing (`-3pmi`). Oracle A MATCH for dhcp, dns_port, their flips and dns-ooo, with the flips firing (`-yoZn`). Its ntp section stalled before the domain started, with no region-share line. That is the second such ntp stall, always in a boot's last section, and the cause is not established. ntp alone then gave stdout DIFFERS, 24 lines, stderr MATCH, status 0 (`-HbqD`).
- runtime-gaps: `c64` MATCH. `i11` shows the runtime line (1) with fd 1 closed. Its first attempt stalled and was retried.
- FFmpeg: M1–M5 and the flip REACHED, 30 frames match, the control FIRES.
- All five tshark images carry the runtime's `__capstone_domain_environ`, constructor loop and
  destructor override.

**Rerun after rebasing onto C-47 (2026-09-25, 07:00).** The runs above were on a tree without
the `compiler/c47-tls` merge. That merge also edits `link.ld` (the TLS segment) and `tls.c`,
which `domain_main` calls before the constructors. So the change was rebased onto `2d2bba8` and
rerun on the combined tree:
- **Runtime probes, dev's compiler `3979abd8e9a3`:** thread-local, init-fini, unserved-report,
  exit-hook, return-flush and stdio-descriptors all pass, each with its control. Thread-local's
  control boot stalled at login once and passed on the retry.
- **tshark, rebuilt on the combined runtime** (the port's compiler `b7b31421e9fa`): M1–M5 all
  REACHED and MATCH (`qemu-stages-20260925-071047-fSrq`), and runtime-gaps `c64` MATCH.

**One stall held the shared QEMU lock for 85 minutes** (`qemu-stages-20260925-044201-DEtw`). The
guest stalled in the 9p copy during setup, before any domain started, the same class as
`-20260924-223429-UkL7`. The runner's guest timeout of 960 s per section, against runs of 15–30 s,
let the stall hold the lock that long against other lanes' jobs. It is now 150 s per section, with
a 120 s alarm per run.

In the full tshark run, the runtime's own line (`capstone-domain: UNSERVED syscalls: 160x5 278x4
134x4 17 135`) now reaches the host and agrees with the port's fd-2 report. Before the fix it was
missing (`qemu-stages-20260925-040726-m6xz` against `-20260924-223202-gu4p`).

**C-65 (not landed).** Two overlay files in `arch-capstone64/`, on the local branch
`musl/c65-pthread-cond` (`85972d2`):
- `bits/alltypes.h.in` declares a 64-byte `pthread_cond_t`/`cnd_t`;
- `pthread_impl.h` `#include_next`s musl's own header and moves the seven `_c_*` macros.

Tested with a private musl cache: `runtime-gaps/run.sh c65` returns with `sizeof = 64` and
"broadcast returned", and the musl build fails the same 6 objects as without the patch. The wait
paths need a futex and were not exercised. It changes the libc ABI for every port, so it is the
lead's decision.
