*RTL lane, 2026-09-16. Branch `m1-reclaimer` in `capstone-ariane`: merge `f714d2a72` → Part B `b49673357`
→ A1 `35081fdb9` → A2 `ac5706553` → A3/A4 `1ac15c4ef` (the gen-blind control) → A5 `d9620b907` → A6 `054cea69b`.
Design authority: `docs/plans/2026-09-16-revnode-reclamation-v2.md` as corrected by its audit. Every
reading here is from a Verilator model at `S12_MEM_DELAY=12` read back from the artifact, with CAPPRINTs
aligned to RVFI retirements by `capstone/tests/capprint-retired.py`.*

## Result in one paragraph

Revocation nodes are reclaimed. A node the walk invalidates is pushed on a LIFO free list (folded into the
write that already happens: the two-node REVOKE costs 252 cycles before and after); an allocation pops
the list first and hands out `(generation+1, index)`, bumping `head` only when the list is empty; a pop
costs 6 cycles more than a bump. The approval test is a pair of consecutive commits on the same tree with
the same fixtures: on `1ac15c4ef` a retained stale reference **succeeds** against the slot's new owner
(stale LDC/MREV/SPLIT/DROP all cause 0; `LCC` of the fresh owner reads 0 afterwards — destroyed; a stale
REVOKE kills a sibling), and on `054cea69b` every one of those arms is **refused** with cause 25 and every
fresh owner is intact (LCC of the fresh owner 1, the sibling 1, 8 traps where the control had 4). Exhaustion is a fault (cause 30), not a hang, since Part B.

**The per-allocation cost, confirmed at N = 65,532.** `alloc_slot()`'s call boundary costs one cycle on
the bump path, measured on a single instruction (bump SPLIT 27 → 28, bump MREV 26 → 27 at the sweep's
default delay). The exhaustion fixture confirms it at scale: it runs **+65,542 cycles** on the reclaimer
against Part B, and it performs **65,532** allocations — one cycle each, residual 10 across the whole
run. A reclaiming allocation costs a further **+6** (a free node's read and the reclaim write), identical
at memory delay 12 and at delay 0 while cold operations differ by an order of magnitude (a cold MREV is
276 cycles at delay 12 against 26 at delay 0), so the +6 is unit-side work on cache hits, not memory
latency. The bump-path mint is otherwise untouched: the reference suite's 282-cycle mint is byte-identical
to A2's at every rung. **All of this cost is A3/A4's; A5 adds nothing measurable** — its reference suite
is identical to A3/A4's cycle stamp for cycle stamp, and the three sweep tests that moved read the same
numbers on a worktree at `1ac15c4ef` as they do here.
## The audit that changed the answer

Every gate was green at A5 and the registry entry was written. An adversarial audit of the finished
diff — run because CLAUDE.md requires one before a "fixed" claim, not because anything looked wrong —
refuted it. `change_rev_node_next/prev` do not mask and `prev`/`next` are 30 bits, so the four sites
that write `*node_id` into a neighbour's link wrote the generation too; the walk reads a link straight
back into `revoke_index`, a push does `free_head := *revoke_index`, and `alloc_slot` composes
`#{g1, 16'd0} + *pop_idx` on the stated precondition that `pop_idx` carries no generation. A2 masked
those same four stores and recorded "an id becomes a link at exactly four stores" — true then, because
`*node_id` was generation 0; A3/A4 made it composed and did not revisit them.

**The symptom is not the one to guess.** The caller rebuilds the record from `node_id`'s top bits, so
record and capability agree on the wrong value and the capability *works*. What breaks is that the
node's generation SKIPS — and the retirement compare fires only at exactly `14'd16383`, so a skip can
step over it and wrap. A wrapped generation is exactly the condition under which a stale reference
becomes acceptable again, which is the guarantee the whole exercise exists to provide.

**No fixture reached it, and the fixture header says why.** A handle's own `next` is masked at the mrev
site, so arriving at a parent from a handle is bare; a SPLIT child is a *sibling*, so it sits at the
walk's termination boundary and is never pushed — both measured, not assumed, on the way to finding a
shape that does reach it. `r12-recl-composed-link.S` uses the mrev handler's `prev_node.next := node_id`
with a reclaimed inner handle. Same fixture, same model, consecutive commits:

| | A5 `d9620b907` | A6 `054cea69b` |
|---|---|---|
| pop 1 | 131075 = (2,3) | 131075 = (2,3) |
| **pop 2** | **196614 = (3,6)** — generation 1 reissued as 3 | **131078 = (2,6)** |
| pop 3 | 8 (bump) | 8 (bump) |

The fix masks at both ends: the four writes, and the three reads of a link into the walk's registers
(`serving_next` alongside `revoke_index`, since the two are compared as the splice guard). Either alone
closes it; both make the allocator's precondition true by construction.

**The lesson is about the order of the gates, not about masking.** Five directed fixtures, a full
sweep, a lint gate and a 16,386-round retirement run were all green on RTL carrying this. The audit was
the only thing that could have caught it, and it caught it because it was pointed at the diff's weakest
claim rather than asked whether the tests passed.

## What the pair cannot distinguish

The PC-capability path (a stale CODE capability needs CALL/RETURN to install); `commit_stage`'s
post-adopt compare race at the tracker; the unit-side belt for `rev_req` (REVOKE's refusal comes from the
preceding query, and the dyn unit runs one operation at a time — written at the site); FIFO-only hazards;
LIFO vs FIFO except by print order. LIFO was built first because its push is free; FIFO is the spec's
recommendation and a follow-on the lead can ask for.

## Instruments that had to be repaired on the way (each negative-tested)

1. `anvil-staleness-check.sh` passed a **zero-byte** generated file: a failed anvil leaves an empty target
   with a fresh mtime, `make` calls it up to date, and the first A3/A4 fixture run went against a model
   that was never built. Fails on EMPTY since parent `47ab6d009c94`.
2. The last-wins CAPPRINT parser merged **distinct consecutive prints of one register** (17 of 29 kept on
   the stale fixture). Replaced by alignment to RVFI retirements (`capstone/tests/capprint-retired.py`,
   parent `f742e71b3b24`), which refuses when a print is left unconsumed.
3. `r12-recl-cpmp` needed three facts about the RTL: `CAPENTER` takes x0 operands; it grants
   `[0x80800000, 0x82000000)`, not `.data`; and an S-mode **fetch** under capmode is checked against the
   CPMP entries (`pmp_data_if.sv:227`), so S-mode code needs a covering entry or every PC traps.
4. Two Anvil borrow-checker rules, each a compile cycle: a `let` of a register is a live borrow until end
   of scope; a `call` result does not live past the next `>>` (copy it into a register in its own cycle).
