**Status:** core fix complete and sim-validated; board synthesis pending (external);

## What S-06 was

An untagged 128-bit `ldc`/`stc` round trip lost or corrupted the high 64 bits on silicon
(and would forge tags). Root cause was 13 sites (D1–D13) across the memory subsystem and
pipeline; the decisive ones: the two dcache read gates zeroing the raw high dword (D1/D2),
single-bank/single-beat untagged writes (D3/D4), the `decompress_cap→compress_cap` round
trip minting `0x0800_0000|(C[20:14]<<20)` for 16 KiB-aligned cursors (D5/D6), and — a live
forgery hazard — `st_wr_cap = |wr_user_i` / `is_cap_req = |dcache_data.user` letting nonzero
plain metadata SET a tag (D7). It had forced three software workarounds, all NOT VIABLE on
silicon (ISSUES.md:766).

## The fix (Option A, the user's contract: untagged ldc/stc copies all 128 bits verbatim,
tag clear; tagged handling untouched)

A real 1-bit tag rides beside every 64-bit compressed-metadata lane (64→65) from the shadow
regfile through the pipeline, the dcache req/resp, the wbuffer, the CSRs and the dom-switch
context. Two choke points make it sound with zero Anvil fat_cap_t changes:
- ingestion forces NOT_CAP when tag=0 (`decompress_cap_tagged`, stashing the raw 64 bits in
  the dead `bound_start`), so raw data aliasing a cap type can never act as a capability;
- egress is bijective (`compress_cap` NOT_CAP branch returns the stash verbatim; tag :=
  cap_type != NOT_CAP), so compress∘decompress is the identity for untagged values.
Memory width is opcode-driven and tag writes are tag-value-driven, never `|metadata|`-driven
— this STRENGTHENS the no-forge invariant.

## Known residual — AMO tag resurrection (NOT closed, separate follow-up)

An AMO on a capability granule leaves both the L1 `cap_tag_q` and the DRAM tag byte set, so a
later reload resurrects a "capability" over AMO-written scalar data (invariant I4 — a real
forgery path, and in scope of the user's "ordinary data cannot set valid tags" even though
the plan scoped the rider as optional/separate). The one-line rider (ATOMIC_REQ into the
tag-write FSM) was attempted and REVERTED: an AMO's ATOP completion does not emit the store
B-response that decrements `tag_wr_pend`, so the next load's tag-read wedges in TAG_WAIT
(reproduced in sim — the post-AMO reload never retires). A correct rider must also invalidate
the line's L1 `cap_tag_q`; both are cache-coherence changes out of the S-06 core scope. Repro:
`verif/tests/custom/capstone/s06sec-amo-no-resurrect.S` (kept out of the testlist so it does
not fail the gate; currently TESTNUM=3 = resurrected).

## Adversarial audits (2026-08-14, on the committed final state)

Two auditors ran against `fpga-testing-dev..HEAD`.

**claim-auditor** (attacking "ordinary data can never forge a tag anywhere"): could NOT
break the P1–P6 scope — the wbuffer merge rules, the 64→65 boundaries, the CSR/CPMP/
dom-switch paths all held under attack. It refuted only the *literal* "anywhere" via the
already-documented AMO residual, and surfaced ONE new asymmetry: a hardware trap wrote the
scalar pc into `mepc` without untagging the paired `cepc` (the software `csrrw mepc` path
does untag). Not an escalation (metadata unchanged; only the cursor moves, bounds-checked at
use by `pc_cap_check`), but a real asymmetry. FIXED: `csr_regfile.sv` trap-entry now clears
`cepc_tag_d`, matching the software path; validated by a full sweep (behavior-neutral).

**rtl-oracle** (RTL vs QEMU): the S-06 contract MATCHES — untagged ldc/stc is verbatim
128-bit with the tag cleared, the 16 KiB-aligned minting path is structurally unreachable for
NOT_CAP, and RTL does not over-clear an untagged linear-looking granule (I3). The divergences
it found are PRE-EXISTING and not touched by the S-06 fix: RTL enforces linear-family
exclusivity across the LDC/STC memory boundary (via `check_load_data` and the STC rs2-clear)
while QEMU enforces it only register-to-register; and the `compress_cap(decompress_cap(...))`
bit-identity for *genuine* (tagged) capabilities across all cursor/bounds values was not
audited (pre-existing compression-scheme behavior, separate scope). Neither is an S-06
regression; the linear-exclusivity difference is the RTL being stricter, not weaker.

Named unresolved items (pre-existing, out of S-06 scope, for a future pass): genuine-cap
compression round-trip identity; wbuffer metadata-half forwarding when a store to `granule+8`
overlaps an in-flight LDC (the store-forwarding tests lsforward/shrink-store-fwd/
stc-neighbour-load cover the structure and are bit-identical); the uncached-bypass tag path
`rd_ctag = |wr_cl_user_i[7:0]`.

## S-08 follow-up (2026-08-15): the fix's own board regression, root-caused same day

The first synthesized bitstream (`caplifive_s06fullfix.bit`) broke userspace ecall
delegation (S-08). Root cause: the P4 phase made every dom-switch context store an
unconditional 16-byte write, but the switcher walks scalar CSR rows at 8-BYTE stride
(process(64'd8, 1'b0, ...)) — each save clobbered the next slot before the exchange read
it; medeleg restored 0. Fixed by honoring metadata_en in the dom-switch width (store and
load sides), commit 9fd5507be. Two structural lessons recorded: (1) NO green sim test
drives the dom-switcher (the ones that do are designed timeouts with unchecked restores),
so the gate was blind to any context-exchange corruption — s06sec-ctx-scalar-roundtrip now
covers it with sentinels; (2) CAPENTER does not drive the switcher at all (verified by
RVFI trace), so capenter-based tests cannot exercise context save/restore.
