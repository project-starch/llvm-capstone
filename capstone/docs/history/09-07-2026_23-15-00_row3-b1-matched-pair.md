## What this closes

row3's "after" was, until now, an abstract probe (`sqlite-borrow-revoke-probe`,
magic sentinel `0x0FA017ED`, does not link SQLite). The plan's step-2 finding
claimed the *literal* single-domain form was blocked on the gated
`start.S`/firmware wall (same as row 11). **B's task-007 falsified that**: the
monitor already delivers a `REV_TRANSFERRED` linear capability into the domain
(`shared_region_annotated` → `__domcallsaves(REGION_SHARE)`, surfaced by
`my_first_domain/start.S` as `domain_main`'s cap argument), so an intra-domain
`MREV`/`REVOKE` needs no firmware change.

So row3 now has a **real-SQLite, single-domain matched pair** (fork B1):

- `benchmarks/sqlite/sqlite_row3_domain.c` — the SAME sequence as `before.c`
  (`open :memory: → CREATE t(a) → INSERT 1 → prepare "SELECT a AS colname" →
  step → column_name → finalize → read name[0]`), real SQLite C API, one Capstone
  domain, one address space.
- The one wrapper: `sqlite3_column_name`'s result is copied into a `SPLIT`-carved,
  independently revocable sub-capability of a **monitor-granted linear arena**
  (region #2, `REV_TRANSFERRED`/`PERM_INOUT`); `sqlite3_finalize` `REVOKE`s it.
- Post-finalize `name[0]` read: host = ASan heap-use-after-free (the "before"
  oracle, unchanged); Capstone = deterministic capability fault.

## Validation (QEMU, serialized under the rootfs lock)

`run-sqlite-row3.sh`, two `.dom`s (fault + no-revoke control), one boot each:

| Domain TU opt | Result | Evidence |
|---|---|---|
| `-O0` fault | **FAULT cause 24** (GREEN) | `badaddr` = the carved buffer; the spilled alias reloads untagged |
| `-O0` no-revoke control | **RETURNS** (GREEN) | reads colname `'c'` live and post-finalize (identical program) |
| `-O1`/`-O2` | QEMU-blocked (see below) | domain-TU codegen bug, not the mechanism; `-O2` asm proves the alias is register-held |

SQLite (the engine) is built at `-O0`; only the domain TU is varied. The
fault-cause evidence lives in the domain TU's `run_row3()`, where the held alias
sits. (The amalgamation also does not compile at `-O2` on this backend — an
`i128 CapstoneISD::SELECT_CC` in `sqlite3_str_vappendf` is not selectable — a
pre-existing codegen limitation, noted in the plan; independent of the below.)

The cause is opt-level dependent (as B's task-007 established): at `-O0` clang
spills the alias, so the post-finalize deref reloads it (`ldc`) and the reload
clears the tag → cause 24 (ambiguous, hence the no-revoke control disambiguates:
same program, no revoke, returns `'c'`). At `-O1+` the alias stays in a register
across the revoke → the intended cause 25 ("on revoked capability": tag intact,
node revoked — self-proving).

**`-O1`/`-O2` QEMU boot is currently blocked (domain-TU codegen bug, B's lane).**
Both opt levels abort QEMU with `helper_csdelin: Assertion rd_v->tag failed`
*before* the revoke — it aborts the **no-revoke control** too, so it is a codegen
robustness bug, **not** a flaw in the revoke mechanism. Root shape: a `.insn`
cssplit's derived capability loses its tag when the optimiser spills it across an
intervening call (`output_text`/`sqlite3_finalize`) with a scalar `sd`/`ld`
instead of a tag-preserving `stc`/`ldc`; `-O0` dodges it because every pointer
local is already in a tag-safe stack slot. B's isolated `intra-domain-mrev-revoke-probe`
carve is `-O2`-green because nothing crosses a non-inlined call there; the SQLite
call pressure is what surfaces it. Fix is B's lane (codegen), tracked in task-008
(same cap-split/allocator territory). The `-O2` asm below is nonetheless the
direct evidence that the intended `-O1+` deref goes through the held capability:

`-O2` asm of the mechanism (domain TU), the direct evidence that the fault goes
through the held capability and not a re-materialised ambient pointer:

```
.insn r 91,1,6, s2, a1, a2   # cssplit: s2 = carved sub-cap [mid,end), fresh rev node
mrev  a1, s2                 # revocation handle
stc   a1, -272(s0)           # ...spilled (the handle, not the alias)
delin s2                     # working alias -- STAYS in s2
... copy colname bytes through s2 ...
call  sqlite3_finalize
ldc   a0, -272(s0)           # reload the handle only
revoke a0                    # lifecycle point
lbu   a1, 0(s2)              # post-finalize read -> through held alias s2, no reload
```

## Honest residual (why B1 is not yet the literal form)

The revoked pointer is a carved **copy** of the column name, not SQLite's own
memsys5 heap pointer. memsys5 allocations are not independently revocable —
`&zPool[i]` is a `cincoffset` that inherits the pool's `rev_node_id`/type/bounds,
and `SPLIT` (the only fresh-node op) has no merge, while memsys5 coalesces (B's
task-007 Step-3 verdict). The literal matched pair (`MREV` of SQLite's own
returned pointer) is fork **B2** — a revoke-on-free non-coalescing linear
allocator, routed to B as task-008. Whether B1's fidelity is the acceptable row3
"after" or B2 is required for the headline is the Q1/lead bar.
