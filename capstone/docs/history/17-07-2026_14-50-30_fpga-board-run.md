# Task 017 — the board run: driver drove the board end-to-end; blocked by a monitor SBI-RFENCE gap

**Date:** 2026-07-17
**Branch:** capstone-bootstrap-b
**Scope:** additive test tooling only (`capstone/tests/rtl-smoke/fpga_driver/`)

## Outcome in one line

The console outage cleared and the driver ran the real board end-to-end (Lock →
power → JTAG-load our `fw_payload.bin` → reset → wait for shell). Our OpenSBI and
**our Linux kernel both boot**, but the board **never reaches a shell**: the
genesys-testing FPGA monitor does not implement the **SBI RFENCE (remote-fence)
extension**, so the kernel's icache flush before `exec`ing `/init` fails in a
tight loop and the board resets ~9 s into userspace. No `.dom` can run yet. This
is a **monitor capability gap → needs a human** (rebuild the FPGA monitor with
RFENCE, or build the kernel to use a local `fence.i` path). Not a driver bug.

## Two things found at the hardware, and how the driver handled them

1. **Load-after-power-on is a transient.** The first `POST /api/load-image`
   immediately after `power_toggle` returned `load_state: error` — OpenOCD/GDB
   can't attach to the JTAG TAP until the core settles. **Fix (committed):**
   `load_boot_image` now does settle-and-retry (3 attempts, 6 s). The second run
   loaded cleanly on the first attempt (core already settled): `load_state:
   loading → done, loaded_image_name: fw_payload.bin`.
2. **Boot reaches userspace, then resets in a loop.** After a clean load + reset:
   - Our monitor runs: `OpenSBI v1.3 for Capstone`, Firmware Base `0x80000000`,
     `Domain0 Next Address 0x80200000` (S-mode).
   - Our kernel runs: `Linux version 6.4.14 (… Buildroot 2023.08 …)`,
     `Machine model: eth,ariane-bare`, reaches `Freeing unused kernel image
     (initmem) memory` and **`Run /init as init process`** at t≈30.7 s.
   - Then **475×** `remote fence extension is not available in SBI v1.0` with
     **zero userspace output**, and at **t≈39.9 s the board resets** back to the
     zsbl ROM (`Hello World! … could not initialize sd… exiting`) → OpenSBI →
     Linux again (`Linux version` appears twice = boot loop).

The driver's `reset` waited the full `prompt_timeout` (180 s), never matched the
prompt (correctly — there is none), raised `ActionTimeout`, and **released the
Lock** in `finally`. Good-citizen behavior intact throughout.

## Root cause

The kernel logs `remote fence extension is not available in SBI v1.0` at boot
(SBI probe of `SBI_EXT_RFENCE` → not present) and then floods it once `/init`
needs an instruction-cache flush. On this single-hart FPGA, exec'ing the
initramfs `/init` requires invalidating the icache for the just-unpacked pages;
Linux/RISC-V routes that through **SBI `remote_fence_i`**, which the
genesys-testing OpenSBI does not provide. The flush never happens, the core
executes stale instructions at `/init`'s entry, faults, and the board resets —
repeatedly. QEMU's OpenSBI implements RFENCE, which is why the same image yields
the QEMU reference numbers but the FPGA cannot reach a shell.

This is **orthogonal** to the earlier monitor-compat finding. That check
confirmed genesys-testing carries the *revoke-cost region-share ABI*
(`REV_TRANSFERRED`/`REV_SHARED`/`DPI_REGION_SHARE`) — still true. RFENCE is a more
basic base-SBI requirement just to boot Linux to userspace, and it is missing.

## What a human needs to decide (the collaborator / monitor owner)

Either, and neither is our-side additive test tooling:

- **Monitor:** rebuild the FPGA OpenSBI (genesys-testing) with the RFENCE
  extension enabled/implemented, and re-flash/serve it on the board. OpenSBI
  ships RFENCE by default; the Capstone fork appears to have it off for this
  platform.
- **Kernel:** build the Linux Image so icache/TLB maintenance uses the local
  `fence.i` path instead of SBI RFENCE (viable on a single-hart target). This is
  a kernel-config/image rebuild, outside the additive-tooling lane.

Until one of these lands, the board cannot run the `.dom`s and there are **no
cycle-accurate numbers to report**. The QEMU reference stands unchanged: bump 7 /
norevoke 60 / revoke 65 → revoke-at-free +5 instr, O(1).
