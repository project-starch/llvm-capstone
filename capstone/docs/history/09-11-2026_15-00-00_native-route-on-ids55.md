# The native route on option B's 55-bit lifetime ids (e5-ids55): what changes, the twin gate, and the board pre-registration

MEASUREMENT ONLY. Branch native/c5a-ids55, from native/c5a-board 8cc014c0bdd2, with bb966f390814 merged. The lead's
target: native perlbench and mcf train on an e5-ids55 bitstream from about Tue 10 Nov 10:00 SG, provided the bitstream
(rtl lane, sealed by Tue 06:00) and this side are both ready.

## Every site that depends on the id width

Option B (capstone-ariane rtl-ids55 325966ee4) uses a 55-bit id {generation[54:25], slot[24:0]}:
- a stored capability keeps the slot in its cursor word's [63:39] and the generation in the hi word's node field
  [63:34];
- a wide flat record keeps the generation at word 1 [59:30] (capstone-qemu cap_rev_table_abi.h CAP_REV_WIDE_*);
- the header is the narrow one;
- the load rule: a plain load of a TAGGED granule's first doubleword reads sext39(address)
  (load_unit.sv:831-837, ex_stage.sv:938).

**Kernel (adapter, kernel patches).**
- The adapter already had the flat 55-bit build: `capstone_vm.c:132-145` (CAPSTONE_VM_IDS, CV_ID_RECORDS_MAX from
  CAP_REV_WIDE_RECORDS) and `:343-358` (INDEX_BITS 25, only with IDS 55 and the flat table, default 2^20 records).
  It comes from the ids55 module lineage (3fd833045f72).
- The in-tree Makefile could not request it. It now takes `CV_IDS=55` (6435589265c0).
- No other site depends on the width:
  - the flat header writes (`:3248-3249`), the free count (`:573`), retired and pushed counting (`:1702-1709`) and
    the CSRETIRE operand (`a->ancestor`, the id CSMINT returned, `:1966`) are width-neutral;
  - the linux-6.4 patches decode no id;
  - `rt-dom.h:230-236` already prints B's slot and generation.
- The 6.4.14 board tree (linux-board-ids55, a copy of the e5-native kits' tree) compiles it. Its .sdata reads
  index_bits 25, ids 55 and node_flat_records 2^20. There is no scapctl or urevavail access.
- The board device tree advertises no copyable profile, so the adapter takes the build's width (`:3397-3402`).

**Firmware (CSCHECK emulation, capstone-sbi).**
- The C.5a/E5 lookup (`capstone_cscheck.S:176-212` at e04ecb8) reads the id from the stored hi word.
- On B the hi word holds only the generation. The slot sits under the load rule.
- native/cscheck-emu-ids55 b366655 adds `CSC_IDS55`:
  - it stores the LDC copy into a firmware scratch granule (STC);
  - a plain store to that granule's second doubleword clears its tag, and a plain load then reads the raw cursor
    word (slot = [63:39]);
  - it compares the 30-bit generation at record word 1 [59:30].
- The frame is never written. The default build assembles to e04ecb8's text.
- **It has not executed.** It needs an RTL-simulation arm on the e5-ids55 RTL, as va-cscheck-mon ran on e5-native.
  Until it runs, a train run on the board is that code's first execution (see prediction 6).

**RTL (rtl lane, not this branch).**
- e5-ids55 must carry CSRUNV action 4 DETACH and 5 | kind << 8 ADOPT and the R-69 resume clamp, as e5-native does.
- 325966ee4 has neither: it predates them, on the bitstream-3 base.

**Twin.**
- capstone-qemu native/c5a-twin55-check is origin/virtual-capstone 0542c5556c (x-capstone-ids=55) plus:
  - x-capstone-cscheck-frame (063b888573);
  - detach/adopt (22860e82a6);
  - the action-3 rule (a41f0e7946);
  - a0501ebc39, a merge repair.
- The QEMU model decodes through cap_uncompress, which is wide-aware (`cap_compress.c:54-57`).
- Not carried: compact rounding (b2c47b34c5, 64442b9126) and the R-60 switch (a36498f352). Their cap_compress
  conflict with the wide encoder is a port of its own. So this twin keeps exact bounds where the 20-bit twin rounded.
- The binary's sha256 starts e44716616ce352dd. The twin kernel (images-ids55/Image, f8899b93c1cc107f) is the twin
  tree with the branch's adapter at 25/55.
- The device trees twin55-c5a.dts and twin55-936-c5a.dts carry id-bits 0x37.

## Twin gate (run-musl-io.py io --c5a-model --twin --ids55 --counters, slot 77)

- **First run, on the 30-bit tree:** the adapter never loaded (no `loaded` line, MUSL_GATE_EXIT:2). That is the
  width check at `:3413` firing against a profile at id-bits 30.
- **With twin55-c5a.dtb: PASS.** The counters equal the 20-bit twin's t20x-io in every field: k3=767, k4=530,
  exchange=393, kinds_queries=226, detaches=2, adopts=2, adopt_kind_refused=0.
- **Control, the same kernel and tree with QEMU at 30-bit ids: also PASS.** This gate does not discriminate the id
  width at its scale. It shows that the native route, including the two-live-task detach/adopt, runs on the 55-bit
  build. It does not show that 55-bit ids are exercised.

## Addendum 1 (9 Nov, before any board run): b366655 is void on B silicon; the fence variant 4f51541

The rtl lane's RTL-simulation arm of CSC_IDS55 on V1 read 25 on rows 3, 4, 5, 9 and 10:
- the `sd zero, 8(t2)` that clears the scratch granule's tag was still in the store buffer when `ld t3, 0(t2)` read
  the still-tagged line;
- CVA6's load/store hazard compare is doubleword-granular, and the store went to dw1 while the load read dw0;
- so B's load rule returned the projected cursor, without the slot.

**b366655 (and kits bkit40-native-ids55-{perl,mcf}, which pin it) is void on B silicon.** Those kits now refuse to
run anyway, because the monitor worktree is no longer at b366655.

capstone-sbi native/cscheck-emu-ids55 4f51541 adds one `fence` between the store and the load. The default build
still assembles to e04ecb8's text. The kits bkit40-native-ids55-{perl,mcf}-fence pin 4f51541 and are otherwise the
same.

The pre-registration above stands with 4f51541 in place of b366655. One more gate before any board run: the rtl
lane's sim arm reads as pre-registered with the fence.
