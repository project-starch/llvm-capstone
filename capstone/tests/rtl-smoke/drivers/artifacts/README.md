# Pinned artifacts the drivers check by hash and that cannot be rebuilt

| file | sha256/16 | why it is pinned |
|---|---|---|
| `lpc` | `3b93a2b6e2adfa36` | the control-rung host every boot starts and ends with (`lpc\|k800`); a pre-merge build linked against the QEMU line's library BEFORE the loader merge (`docs/plans/monitor-unification.md`, the `lpc` paragraph): a rebuild links the merged `libcapstone.c`, which packs `.capstone_gp_initdesc` into `entry_offset` and synthesises across all `PT_LOAD`s — a different image shape the board has not validated. Every boot in the measurements doc used these bytes. 8,240 bytes, no build-host strings. |

`SHA256SUMS` is the manifest: `sha256sum -c SHA256SUMS` before staging. A successor copies `lpc` into the
overlay (`${CAPSTONE_BR_OVERLAY}/lpc`); `board-r1e4.sh` refuses any other hash at its `:41` gate. The
`k800.dom` rung is NOT pinned: it is rebuilt from `tests/runtime-qemu/silicon-ladder/` and its oracle
regenerated by the ladder's verify step (its result line `RESULT k800 retval=4` is the control's oracle).
