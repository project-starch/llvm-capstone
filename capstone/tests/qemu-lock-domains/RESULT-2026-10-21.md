# QEMU lock domains: control readings, 2026-10-21

Kit qkit7 (QEMU 7a4f3a64, module 5bfc38f8). Every control held the REAL global lock exclusive for its whole run, so no
other QEMU session ran beside it; the reader-writer semantics were exercised on private lock files inside that hold.
Runs: run.sh (a)-(d') then run-b.sh (forced (b)). Result lines below, quoted from the RESULT files.

- (a) PASS. Two snapshot-class run-staged.py sessions, domains A and B, both granted at 1792588228.8 and both ended at
  1792588273.2: they overlapped. Each serial log carries only its own markers (A-own:A-foreign:B-own:B-foreign 2:0:2:0).
  The shared rootfs.ext2 hashed 9903242c37a72425 before and after.
- (b), first attempt: NOT a reading. QEMU refused the second writable session: `Failed to get "write" lock / Is another
  process using the image`. QEMU's own image locking already forbids two processes opening one image writable. That is a
  second protection, independent of ours, but it left this detector unexercised.
- (b) forced, with `file.locking=off` on the scratch drive: FIRES. Both sessions ran. A listed `marker-A`, B listed
  `marker-B`, and the shared file ended holding only `marker-A`: a LOST UPDATE. e2fsck -fn stayed clean (rc 0), so a
  filesystem check alone would not have caught it.
- (c1) PASS. An exclusive holder for 30 s (from 2 s before the session): the domain session's grant waited 27.9 s.
- (c2) PASS. During a domain session, `flock -x -w 10` on the global lock timed out (rc 1 after 10.0 s); after the
  session ended it succeeded at once (rc 0 after 0.0 s).
- (d) PASS, the turnstile. D1 granted 1792588376.4, ended 1792588410.1; the exclusive waiter X (through the turnstile)
  granted 1792588410.192; D2, which arrived after X queued, granted 1792588415.2. X ran when D1 ended and before D2.
- (d') PASS, the negative twin. With X taking the global lock WITHOUT the turnstile: D2 granted 1792588422.8 while D1 still
  ran, X only at 1792588452.351. The starvation is real, and the turnstile is what prevents it.
