== WHAT THIS LICENSES, AND WHAT IT DOES NOT ==
# LICENSES: the optimistic adopt exists in the RTL SOURCES and is sufficient on its own to let an
#   in-bounds, permitted access through a revoked NONLIN capability read and write without trapping.
#   That is a source-level property of 054cea69b, independent of placement, routing and timing, so
#   it removes the 'artefact of a build with WNS -8.307 / 90,379 failing endpoints' alternative for
#   the MECHANISM. The board probe is rotated too (reuses_since 0/1353/2706 with live-alias writes
#   in between), so the two observations line up.
# DOES NOT LICENSE: that the placed-and-routed netlist behaves this way -- only that it need not be
#   blamed. And it does NOT account for results/board-cause-probe.wedge.txt or
#   results/board-bounds-probe.wedge.txt: those wedges were NOT reproduced here and stay unexplained.

== ATTRIBUTING THE SILENT TRAPS TO THE LSU, which the silence alone does NOT establish ==
# commit_stage.sv ALSO contains zero $display, so 'absent' licenses only 'not an anvil unit'.
# The LSU attribution rests on three further facts:
#  1. UNIT-LEVEL POSITIVE CONTROL. The fourth trap is a plain sd through an integer base retiring
#     mcause 24. Cause 24 for a STORE is emitted at exactly one place, load_store_unit.sv:973-975.
#     So cap_violation_detection demonstrably reached the exception path IN THIS RUN, and its
#     exceptions are silent. This is the control the earlier FLU-based attempt lacked.
#  2. DECODE ROUTING. decoder.sv:1080-1081 gives OpcodeLoad fu = LOAD with no capmode remap, and
#     the DYN dispatch matches only capability fu_ops, so a plain ld never enters the DYN unit.
#     pmp_data_if.sv cannot emit 25 at all (only 1/5/7) and is gated priv != M; we are at M.
#  3. COMMIT_STAGE EXCLUDED. commit_stage.sv:197 sets the entry PC cap's revnode_id = 1 and nothing
#     here changes the PC capability, so its adopt can never re-fire; once its valid bit went to 0
#     every later committed instruction would trap. ~296k clean retirements say it never did.

== THE PAIR IS SINGLE-VARIABLE ==
# ARM A and ARM B differed in TWO things: the intervening access through a different revnode, and
# the trap-and-mret arm A takes. ARM A2 -- a second un-rotated load -- also traps 25, so the trap
# did not re-validate the tracker. ARM A2 and ARM B therefore differ in exactly ONE thing.
# Corroborated in source: nothing but cap_violation_detection writes the tracker; its always_ff
# has no flush, exception or kill term.

== WHY THIS IS NOT A CORNER CASE ==
# A single core-wide tracker rotates on EVERY access through a different capability, so for any
# M-mode program touching two or more capabilities the revocation check is effectively VACUOUS:
# cause 25 can only ever fire for a program that never rotates. The adopt is gated on lsu_ctrl.valid
# at EXECUTE rather than commit, so a SPECULATIVE access rotates the tracker as well.
