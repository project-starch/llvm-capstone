Checks that make these numbers mean something:

  mepc  -> VA 0x104ba0 = sqlite3WhereCodeOneLoopStart+0x8c, the faulting cincoffsetimm.
  s0-sp = 0xc40 = the prologue's 0x7f0 + 0x450, so the core is halted inside that
        function's own frame, past its prologue and before any further call.
  s0    = 0x82b9f3d0, BIT-IDENTICAL to the previous firing boot -> deterministic call depth.
  tag address: 0xBC2D2D2D + ((0x82b9f360 - 0x80000000) >> 4) = 0xBC58CC63, the address read.
  granule data == the value the group-9 store watchpoint recorded being written (0x82be4cf0).

Reading:

  memory holds the value AND the tag byte is 1  -> the memory path did NOT lose it
  tval = 0                                      -> the consumer was handed cursor 0
  therefore the value was never DELIVERED, not never STORED

Limit that travels with this: a DRAM read reports what DRAM holds, not what the load saw.
The documented issue/return desync runs DRAM-stale-high with L1 correct-low; the mirror case
is UNRESOLVED. So this excludes memory having LOST the value. It does not on its own prove
the load returned what memory holds.
