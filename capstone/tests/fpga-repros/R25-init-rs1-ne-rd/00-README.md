> (this package's test FAIL 11 → PASS), lint at the baseline counts, 88-row sweep unchanged. **Bitstream: SYNTHESISED 2026-09-09 from `66c4e7517`
> (sha256 `b03bd967…52da3`, WNS −12.425 ns at 40 ns, 169,207 placed LUTs), BEING FLASHED 2026-09-09 on the
> project lead's decision; the post-flash reading is filed below when boot sw45 lands.** **Pre-flash silicon reading
> 2026-09-09 (boot sw41): duplicate PRESENT on `caplifive_s12fix_5097eb166`**, as predicted; the post-flash reading is filed below when the fixed bitstream has booted.

**Wrong symptom? Read this paragraph first.** This package is the **linearity break**: after `INIT rd, rs1, imm` with
`rd != rs1`, the source register still holds a live LINEAR capability to the same region, under the same
revocation-node id, as the destination. It raises nothing. Two neighbours are not this issue: `../R26-ccsrrw-stale-cpmp/`
(a younger load checked against a CPMP entry a pending `CCSRRW` is about to replace) and `../R27-revnode-orphan-response/`
(a flush during a revocation-node query leaves the core dead). Two divergences found while building the silicon probe
belong to the registry, not here: QEMU's `INIT` asserts `cursor == end` while spec and RTL require `cursor > end`
(registry Q-07), and the RTL's capability-type numbers are not the spec prose's (RTL UNINIT = 4, spec "3").

## The defect in one paragraph

`INIT` is specified as `MOVC rd, rs1` followed by retyping `rd` to LINEAR with cursor `base + imm`; MOVC of a
non-NONLIN source writes `cnull` to the source. The RTL (`core/anvil_build/capstone_flu_unit.anvil`, INIT block)
built the new capability and passed it as BOTH write-back values — `create_result_pack(..., rd, rd)` — unguarded, where
its siblings guard on `rs1 == rd`. QEMU nulls `rs1`, so the defect was invisible there; every compiled INIT uses
`rd == rs1`, so the sweep never saw it; it is reachable from `-O1/-O2` code that happens to allocate differently.
The duplicate is **usable**: a store through it and a load back through `rd` return a capability (phase 4 of the test,
pre-fix). Security-model violation: two live linear capabilities to one region.

## The test (`sim/init-rs1-ne-rd.S`, self-checking; entry `init-rs1-ne-rd` in `testlist_capstone.yaml`)

Detector: `CINCOFFSET reg, reg, zero` traps `UNEXPECTED_OPERAND` (cause 25) iff `reg` is NOT_CAP and is a no-op on a
LIN/NONLIN register. Eight phases with a per-phase trap count; exit code = `gp`.

| phase | sequence | conformant | R-25 RTL |
|---|---|---|---|
| 0 | MOVC of a LIN source, probe the source | 1 trap (25) | same — the detector's positive control |
| 1 | probe the MOVC destination | 0 | 0 |
| 2 | `INIT a6, a5, 0` with `a5` UNINIT (cursor past end), **probe `a5`** | **1 trap (25)** | **0 traps → exit 11** |
| 3 | probe `a6` | 0 | 0 |
| 4 | STC through `a5`, LDC back through `a6`, probe | 2 traps | 0 traps (the duplicate works) |
| 5–7 | the same with `rd == rs1`, then MOVC out and probe | 0 / 1 / 0 | same |

Exit codes: 10 detector dead · **11 R-25 present** · 12 a destination is not a capability · 13 the same-register arm
broken · 20 unexpected cause. **Read on `ef5a8eaf2`: FAIL 11** (`a5` and `a6` both print cursor `0x…3200`, type LIN).
**Read with the fix: PASS after 967 cycles**, phase 2 traps 25 (`a5` NOT_CAP), phase 4 two traps, phases 5–7 unchanged.

Operand construction, which the silicon probe copies: the UNINIT operand must have `cursor > end` (RTL INIT
`rs1.cursor <= end → ILLEGAL_OPERAND_VALUE`; stores through an UNINIT advance the cursor only to `end`), so the test makes
a LIN capability over a 256-byte window, `CINCOFFSETIMM +272` (the RTL does not enforce the spec's past-end rule), then
retypes in place with the raw `.insn r 0x7B, 0x0, 0x5, CREG, a0, CREG` (the decoder always retypes `rd`; the type
value is the low three bits of the `rs1` register — **4** for UNINIT on this RTL).

## The fix (`fix/42a141c93-capstone_flu_unit.anvil.diff`)

Guard on the register index, as the siblings do: `rs1 == rd` keeps `(rd, rd)`, otherwise `rs1` receives `cnull`. Not
an unguarded `cnull` (SEAL's form), which would clobber the `rd == rs1` shape. Only the `.anvil` is committed;
`core/*.anvil.sv` is regenerated by `make -C core/anvil_build`. Gates: lint LATCH 52 / MULTIDRIVEN 3 / ALWCOMBORDER 0 /
COMBDLY 0 / UNOPTFLAT 40 / BLKSEQ 2 / UNDRIVEN 25 / UNUSEDSIGNAL 717 / ANVIL 0 (= baseline); 88-row sweep identical
to the `ef5a8eaf2` record in status, RVFI hash and cycles.

## Board

**2026-09-09, boot sw41, current silicon `caplifive_s12fix_5097eb166`, firmware `ffefa4eec605` (Q-06 line), board lane.**
Control `k800` = 4 (boot valid). `r25same` (CAPTYPE with RTL type 4, `INIT rd == rs1`, delin, stc, ldc, tag check) =
`0x25000001`: the construction works inside a domain. `r25dup` (`init a3, a1, a0`, then a capability store THROUGH `a1`,
the consumed source, and a tagged read-back) = `0x25000001`: **the store through the consumed source landed and a tagged
capability came back — the duplicate is present on the current silicon**, exactly the pre-flash prediction below. Zero
fault tags, two HOLE lines (the transferred arenas), core alive, both domains answered both CALLs identically. Rows in
`tests/board-results/2026-09-05.tsv` (sw41); registry R-25 carries the same paragraph. Probe construction notes: the type
constant must be the RTL's 4, and the UNINIT operand's cursor must be moved past `end` with CINCOFFSET (RTL does not
enforce the spec's bound there) — the two divergences named in the first paragraph.

**Post-flash (bitstream from `66c4e7517`): not yet booted; boot sw45.** Prediction on file, written before it:
`r25same` unchanged at `0x25000001`, and `r25dup` traps 25 at the store through the consumed source. A capability
trap is a WEDGE on this RTL, so that reads as **wedged after `ENT1` with cause 25 latched by the tracer**, not as
a returned value — which is why the probe runs LAST in its boot. A returned `0x25000001` would mean the duplicate
survived the fix. This is the only one of the three fixes whose post-flash boot can confirm anything: R-26's
variant boots and R-27 have no arm that distinguishes a working fix from an untriggered one.
