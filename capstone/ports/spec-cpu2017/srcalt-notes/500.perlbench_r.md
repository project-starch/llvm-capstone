500.perlbench_r src.alt "capstone": research build for the Capstone virtual profile
(128-bit capability pointers, 64-bit long and IV). Not approved by SPEC; results
built with it are not reportable. Each change carries a "capstone" comment in the
source. Most follow the llvm-capstone Perl 5.36 port patches (numbers below).

spec_config.h     PTRSIZE 16 and MEM_ALIGNBYTES 16 under __CAPSTONE_PURECAP__
                  (SPEC hard-codes the LP64 values).
pad.h             PADOFFSET stays 64-bit when PTRSIZE is 16.
perl.h            PTRV and DPTR2FPTR/FPTR2DPTR without an integer round trip (0004).
sv.c              body_details sizes U8 -> U16: 16-byte pointers overflow U8 (0001).
hv.h              hek_key 16-byte aligned: HeKEY_sv keeps an SV* there, and at
                  offset 8 it was copied as integers and lost its tag.
cv.h              PoisonPADLIST for PTRSIZE 16 (DEBUGGING builds only).
doio.c            Zero(mode, PERL_MODE_MAX) instead of sizeof(mode): a real Perl bug,
                  sizeof of a pointer parameter; with 16-byte pointers it wrote 16
                  bytes into an 8-byte array (bounds fault on the first open()).
gv.c              the stash cache stores a pointer in an IV; disabled where pointers
                  are wider than IVs (the cache is transparent).
mro_core.c        registered MRO algorithm pointer in ext magic instead of a UV.
cpan/Digest-SHA/SHA.c  state pointer in ext magic (as Digest::MD5 does) instead of an IV.
op.c              S_maybe_multideref's counting pass does arithmetic on a NULL
                  arg_buf; it now walks a dummy base (0002/0003 era fix).
pp_ctl.c          rxres_save/restore keep saved regex pointers in pointer-typed
                  fields, not UVs (0007).
util.c            my_popen/my_pclose through the C library's popen/pclose (a domain
                  cannot fork; 0008, with the pclose-after-release order of llvm-capstone
                  PR #243), and Perl_repeatcpy copies with memcpy, not bytes, so the
                  list form of `x` keeps SV pointers' tags (port patch 0012, PR #244).

Inputs: t/op/pack.t is not a source file. Four of its checks rebuild a pointer
byte by byte and cannot pass on any capability machine; the kit's
tools/perl-pack-stub.py stubs them in the STAGED copy at run time.
