502.gcc_r src.alt "capstone": research build for the Capstone virtual profile
(128-bit capability pointers, 64-bit long and HOST_WIDE_INT). Not approved by SPEC;
results built with it are not reportable. Changed lines carry "research build"
comments.

spec_qsort/spec_qsort.c  swap unit void * instead of long, so pointers keep their
                  tags (same change as 505.mcf_r's).
ggc-page.c        page-group alignment rounds a pointer through size_t (SPEC turns
                  mmap off, so the malloc path runs); now pointer + offset.
include/obstack.h obstack_finish keeps the object in a pointer field (temp_ptr) and
                  aligns by pointer + offset; obstack_free passes obj itself, not
                  (obj - chunk) + chunk, which was derived from the chunk being freed
                  (cause 25 in build_null_declspecs).
obstack.c         DEFAULT_ALIGNMENT/ROUNDING include void *; COPYING_UNIT void *.
include/splay-tree.h  splay_tree_key/value are __uintcap_t/__intcap_t: gcc stores
                  pointers in them.
alloc-pool.c      align_eight rounds to 16: pool elements begin with a pointer
                  (cause 6, misaligned capability store, in pool_alloc).
sbitmap.c         sbitmap_vector_alloc aligns the table and each bitmap to
                  struct simple_bitmap_def, which begins with a pointer (cause 6).
reload1.c         count_spilled_pseudo read hard_regno_nregs[r] before checking
                  r < 0: an out-of-bounds read in GCC 4.5 itself (cause 28). The read
                  now follows the check, as GCC 4.8 has it.
tree-ssa-sccvn.c  vn_nary_may_trap read nary->op[1] for every operation, but the
                  record is allocated with only `length` operands: for a unary
                  operation an out-of-bounds read in GCC 4.5 itself (cause 28 on the
                  train input 200.c). Read only when length >= 2, as the later
                  releases/gcc-4.5 branch does.
